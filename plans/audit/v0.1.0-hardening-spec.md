## PR 0: Repository Safety

### 0.1 — Data Artifact Audit & Removal

**Decision:** Remove files from current branch immediately. History scrub is mandatory if inspection finds real or uncertain sensitive material; otherwise it is a documented risk-acceptance decision.

**Inspection procedure:**
1. Inspect every file under `email/` and `drive-download-*/` for: PII, PHI, email headers, names, identifiers, credentials, internal URLs, proprietary metrics
2. Document findings in a private inspection note (not committed)
3. Decision point:
   - **If anything is real or uncertain:** Proceed to full history scrub (step 4+)
   - **If entirely synthetic/non-sensitive:** Skip scrub, accept residual risk in git history, document decision
4. If scrubbing: stop merges, record current `main` SHA in a private backup clone or local bundle
5. Run `git filter-repo --path email/ --path "drive-download-*/" --invert-paths`
6. Verify rewritten history has no matching paths or blob references
7. Force-push every affected branch/tag; delete obsolete remote branches/tags that retain blobs
8. Tell collaborators to discard old clones or follow a precise reset/re-clone procedure
9. Acknowledge: if files were ever in a public remote, historical copies/forks may persist; history rewriting reduces repository exposure but does not guarantee global erasure

**Regardless of scrub decision:**
- Add `.gitignore` rules for `email/`, `*.eml`, `data/`, `uploads/`, `exports/`
- Create `tests/fixtures/README.md` documenting synthetic data provenance
- Create `SECURITY.md` with private vulnerability reporting channel
- Create `LICENSE` (MIT)

### 0.2 — Fix Failing CI Pipeline

1. Run `python -m pytest tests/ -v --tb=short` locally, capture failures
2. Fix any broken tests
3. Push to a test branch, confirm GitHub Actions passes
4. Update `cloudbuild.yaml` stale comment ("171 tests" → remove count entirely)

### 1.5 — Escape Exports

**Files:** `utils/report_exporter.py`

### 1.7 — HTML Safety Baseline

**Combined rule:** Remove `unsafe_allow_html=True` wherever Streamlit primitives can replace it. For markup that must remain (static source-controlled CSS/structural wrappers), apply `html.escape()` to every interpolated user-supplied, file-derived, model-generated, or dataset-derived value. Treat "static today" as insufficient protection against future edits.

**Where custom HTML must remain:**
```python
from html import escape

safe_label = escape(str(untrusted_label), quote=True)
st.markdown(
    f'<span class="column-badge">{safe_label}</span>',
    unsafe_allow_html=True,
)
```

**Do NOT use HTML escaping as a substitute for a content-security policy:** never interpolate raw AI output, filenames, column names, formulas, funnel steps, or API error text into markup.

**Files & changes:**

| File | Location | Fix |
|------|----------|-----|
| `components/hero.py` | Hero card, spacers | Replace spacer-only markup with `st.divider()`, `st.caption()`, normal Markdown. Remove `unsafe_allow_html=True` for hero card content where possible |
| `components/chat.py` | `_render_usage_stats()` | Use `st.caption()` / `st.markdown()` without unsafe_allow_html for static labels; escape any dynamic text |
| `components/data_preview.py` | Column type badges | Replace HTML badges with `st.caption(f"{icon} {escape(col)}")` per column |
| `components/data_preview.py` | Spacer divs | Use `st.divider()`, `st.markdown("")` |
| `components/sidebar.py` | Custom metric names/formulas | Use `st.caption(f\"**{escape(name)}** = `{escape(formula)}`\")` |
| `components/sidebar.py` | Model metadata | Use `st.caption()` / `st.markdown()` components |
| `components/sidebar.py` | Privacy notice | Use `st.info()` or `st.markdown()` with escaped text |
| `components/sidebar.py` | Logo/title, section headers | Replace with `st.markdown()` components; validate theme: `VALID_THEMES = {"dark", "light"}` |

**Theme validation:** In `utils/styles.py`, add `VALID_THEMES = {"dark", "light"}` and validate before any CSS/JS interpolation. Never interpolate filenames, uploaded data, AI answers, user names, or query parameters into CSS/JS templates.

**`RELEASE_CHECKLIST.md` structure:**

```markdown
# v0.1.0 Release Checklist

Release candidate SHA: `________________`
Date: `________________`
Release owner: `________________`
Independent reviewer: `________________`

## Repository safety
- [ ] `email/` and `drive-download-*/` removed from current tree
- [ ] History rewrite completed and post-rewrite verification recorded (or risk-acceptance documented)
- [ ] `.gitignore` and fixture-provenance policy prevent recurrence

## Security and privacy
- [ ] OAuth state/callback tests pass
- [ ] Export injection tests pass (Excel/Sheets, PDF, Markdown)
- [ ] No raw exceptions or tracebacks shown in production mode (`SHOW_DEBUG_DETAILS=false`)
- [ ] Privacy, Gemini, Drive, and OAuth disclosures reviewed and accurate

## Quality gates
- [ ] Clean checkout: CI passes (`python -m pytest tests/ -v --tb=short`)
- [ ] Required scenario tests pass (upload, custom metric, filter-to-zero, clear/reload, summary/chat failure, data-version invalidation)
- [ ] GA4 pagination has tested limit/continuation policy (hard cap at 500k with visible warning)
- [ ] Drive permission scope explicitly documented and justified (`drive.file` only, no `drive.readonly`)

## Product integrity
- [ ] Funnel labeled as "Page-path aggregation" with visible caveat
- [ ] Forecast labeled as "Linear trend projection" with assumptions disclosed
- [ ] API telemetry centralized in service layer
- [ ] Summary uses selected model (not always default)
- [ ] Streaming errors rendered as error states (not saved as assistant responses)
- [ ] Chart extraction is explicit opt-in (not silent background call)
- [ ] GA4 property IDs validated before pull

## Infrastructure
- [ ] `SECURITY.md` present
- [ ] `LICENSE` (MIT) present
- [ ] `.gitignore` covers all cache/artifact paths
- [ ] `.env.example` documents all configurable env vars
- [ ] `docs/_build/` removed from tracking
- [ ] Pre-commit hooks include secret scanning and large-file detection
- [ ] GitHub Actions installs from `requirements/dev.txt`, runs lint + tests + coverage

## Release
- [ ] Deferred-items issues created with acceptance criteria, labeled `post-v0.1.0`
- [ ] CHANGELOG updated with v0.1.0 entry
- [ ] Git tag `v0.1.0` created
- [ ] No known critical exceptions at time of tag
```

Do not allow a checklist item to be marked complete merely because code was changed; each checkbox needs a linked test result, PR, commit, or review note.
