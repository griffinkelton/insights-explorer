## Phase 1: P0 — Block Release 🔴

**Goal:** Fix the 7 items that GPT-5.6 identified as must-fix before any release. These are runtime crashes, security issues, and trust-breaking behaviors.

### 1.1 — Fix All DataFrame Boolean-Context Crashes

**Affected files:** `components/chat.py`, `components/summary.py`, `components/data_preview.py`

**Problem:** `custom_metrics_df or df` raises `ValueError: The truth value of a DataFrame is ambiguous` when custom metrics are populated.

**Fix:**
- Create `active_dataframe()` helper in `utils/session.py`:
  ```python
  def active_dataframe() -> pd.DataFrame | None:
      custom_df = st.session_state.get("custom_metrics_df")
      return custom_df if custom_df is not None else st.session_state.get("df")
  ```
- Replace all `custom_metrics_df or df` / `custom_metrics_df or display_df` patterns across chat.py (L1), summary.py (L1), and data_preview.py (L2, L3)
- Add regression test with non-empty `custom_metrics_df`

**Tests needed:** Test `active_dataframe()` with: None custom_metrics_df, empty df, populated custom_metrics_df, no df

### 1.2 — Fix Clear Data Prevents Reload

**Affected files:** `utils/session.py`, `components/sidebar.py`

**Problem:** `clear_data()` doesn't reset `last_file_id`, so user can't reload the same file after clearing.

**Fix:**
- Add `st.session_state.last_file_id = None` to `clear_data()`
- Test sequence: load file A, clear, reload A successfully

**Tests needed:** Integration test: load → clear → same file reloads

### 1.3 — Fix Empty-Filter Stale Data Fallback

**Affected files:** `components/data_preview.py`

**Problem:** When filters return zero rows, `filtered_df = None` — then metrics/preview fall back to full dataset while showing "no results" warning.

**Fix:**
- Keep the empty DataFrame as result; do NOT set `filtered_df = None`
- Render explicit empty state instead of falling back to full data
- Add `filters_active` flag to distinguish "no filter applied" from "filter returned zero"

**Tests needed:** Nonempty filter, zero-row filter, reset filters, new upload after filters

### 1.4 — Secure OAuth State

**Affected files:** `utils/ga4_client.py`

**Four sub-fixes:**

**1.4a — Bind callback exchange to stored redirect URI**
- In `exchange_code()`, validate `redirect_uri == stored["redirect_uri"]` and use `stored["redirect_uri"]` for flow reconstruction
- Raise `ValueError` on mismatch

**1.4b — Atomic writes with restrictive directory permissions**
- Create state directory with `0o700` before use
- Write to `NamedTemporaryFile`, set `0o600`, then `os.replace()` atomically
- Fail closed if permissions can't be secured

**1.4c — Bounded cleanup**
- Verify both filesystem age AND parsed `created_at` timestamp
- Set max state-file count (e.g., 100)
- Don't just rely on save/load triggering cleanup

**1.4d — Token revocation logging**
- In `_revoke_token()`, check `response.ok` and log status code on failure
- Use `data=` (not `params=`) for proper form-encoding

**Tests needed:** URI mismatch rejection, expired state, malformed state JSON, concurrent writes, revocation HTTP status logging

### 1.5 — Escape Exports (Formula Injection + Markup)

**Affected files:** `utils/report_exporter.py`

**1.5a — Excel formula injection prevention**
- Create `safe_spreadsheet_value()` helper that prefixes `'` for values starting with `=`, `+`, `-`, `@`
- Apply to: all DataFrame cells in Data sheet, summary lines, Q&A cells, data source, column names

**1.5b — PDF XML/markup escaping**
- Import `xml.sax.saxutils.escape`
- Create `safe_pdf_text()` helper
- Apply to every `Paragraph()` call: questions, answers, summaries, source labels, statistics

**Tests needed:** `=HYPERLINK(...)` payload, `@SUM(1+1)`, `<script>` in PDF text, `&` and `<` characters

### 1.6 — Stop Exposing Raw Errors to Users

**Affected files:** `utils/error_boundary.py`, `utils/gemini_client.py`, `utils/data_loader.py`, `components/__init__.py`, `components/sidebar.py`, `app.py`

**Four sub-fixes:**

**1.6a — Error boundary: hide tracebacks in production**
- Add `SHOW_DEBUG_DETAILS` env var (default: False)
- Log full traceback server-side with UUID error ID
- Show users only: generic message + error ID
- Only render tracebacks when `SHOW_DEBUG_DETAILS=true`

**1.6b — Gemini client: stop returning raw errors**
- `_classify_api_error()`: remove `f"Unexpected error: {e}"` fallback — use generic message
- `validate_api_key()`: stop returning `f"API key rejected: {e}"` — return stable message
- Log original exceptions privately

**1.6c — Data loader: stop exposing parser internals**
- `load_file()`: replace `f"Failed to parse file: {str(e)}"` with stable message
- `load_drive_file_as_df()`: same treatment

**1.6d — Sidebar/callback: stop exposing raw API errors**
- Replace `st.error(f"Failed to pull GA4 data: {e}")` with generic message + logged error ID
- Replace `st.error(f"Drive error: {e}")` with generic message
- Replace `st.error(f"Authentication failed: {e}")` with generic message

**Tests needed:** Production mode does NOT render raw tracebacks/exception strings; debug mode does

### 1.7 — Fix Unsafe HTML Interpolation

**Affected files:** `components/chat.py`, `components/data_preview.py`, `components/sidebar.py`, `components/summary.py`, `components/hero.py`

**Problem:** Column names, custom metric names/formulas, model names, funnel step labels, and error messages are f-stringed into HTML with `unsafe_allow_html=True`.

**Fix pattern:**
- Use `html.escape()` for any dynamic value inserted into HTML strings
- Prefer safe Streamlit primitives: `st.caption()`, `st.code()`, `st.write()`, `st.metric()`
- Only use `unsafe_allow_html=True` for static, source-controlled markup (CSS, theme tokens, structural HTML)
- Add `VALID_THEMES = {"dark", "light"}` check in styles.py

**Specific locations:**
- `chat.py`: `_render_usage_stats()` — model name and token counts in f-string HTML
- `data_preview.py`: column type badges with column names in HTML
- `sidebar.py`: custom metric names/formulas, model metadata, privacy notice text
- `hero.py`: replace spacers with `st.divider()`/`st.caption()` where possible
- `components/__init__.py`: footer with privacy text

## Phase 2: P1 — Correct User Trust 🟡

**Goal:** Fix claims that are materially inaccurate and misleading to users.

### 2.1 — Rewrite Privacy Claims

**Affected files:** `components/sidebar.py`, `components/__init__.py`, `README.md`

OAuth uses temporary authorization state stored briefly to complete sign-in. Exports and Drive actions occur only when you choose them."

**Also:**

- Document OAuth state-file location, retention, cleanup
- Remove "in-memory only" from footer in `components/__init__.py`

### 2.2 — Rename Funnel → Page-Path Aggregation

**Affected files:** `components/data_preview.py`, `utils/funnels.py`

**Changes:**
- Expander title: "🔻 Funnel Analysis" → "🔻 Page-Path Aggregation"
- Caption: "Define a conversion path and visualize drop-off at each step" → "Compare page-volume totals for selected path patterns. This is not user/session conversion tracking."
- Chart title: "Sessions Funnel" → "Sessions by Page Pattern"
- Docstring in `build_funnel_data()`: clarify it's page-pattern aggregation, not conversion funnel
- Use `regex=False` in `str.contains()` for literal matching

### 2.3 — Rename Forecast → Linear Trend Projection

**Affected files:** `components/data_preview.py`, `utils/forecasting.py`

**Changes:**
- Expander title: "📈 Metric Forecast" → "📈 Linear Trend Projection"
- Caption: "Linear regression trend projection with 95% prediction intervals" → "Linear regression trend projection. Intervals are approximate model-based estimates, not validated forecasts."
- Confidence labels: "strong"/"moderate"/"weak" → add "R² = X (in-sample fit, not forecast accuracy)"
- Fix `build_forecast_summary()`: zero-slope should say "remain broadly stable" not "decline"

### 2.4 — Centralize API Telemetry

**Affected files:** `utils/gemini_client.py`, `components/chat.py`, `components/summary.py`

**Problem:** `api_call_count` incremented in chat before streaming, in `_track_usage()` after success, manually in chart retries. Summary doesn't increment at all.

**Fix:**
- Remove all `api_call_count += 1` from UI components (chat.py, summary.py, command pills)
- Centralize in `_track_usage()` as `api_success_count`
- Add separate `api_attempt_count` and `api_failure_count` if needed
- Display: "7 successful Gemini calls, 1 failed attempt"

### 2.5 — Make Summary Use Selected Model

**Affected files:** `components/summary.py`

**Problem:** `_generate_summary()` calls `generate_response(summary_prompt)` without model argument — always uses `DEFAULT_MODEL`.

**Fix:**
```python
model = st.session_state.get("selected_model", DEFAULT_MODEL)
st.session_state.summary = generate_response(summary_prompt, model=model)
```

### 2.6 — Fix Streaming Error Semantics

**Affected files:** `utils/gemini_client.py`, `components/chat.py`

**Problem:** `generate_response_stream()` yields error strings instead of raising. They get saved as assistant responses, fed to later prompts, exported to reports.

**Fix:**
- In `generate_response_stream()`: raise `RuntimeError` instead of yielding error text
- In `_stream_chat_response()`: catch `RuntimeError` and set `entry["error"]` instead of `entry["response"]`
- Render errors as `st.error()`, exclude from conversation history and exports
- Fix empty-stream bug: track `final_chunk`, only inspect when not None

### 2.7 — Make Chart Extraction Explicit

**Affected files:** `components/chat.py`

**Problem:** Second Gemini call silently made for nearly every long response, bypasses rate limiting, swallows failures with `except Exception: pass`, surprises users about token usage.

**Fix:**
- Add user toggle: "Suggest chart when useful" (default: off)
- Include chart-extraction attempts in telemetry
- Log failures at debug level
- Show "Chart suggestion unavailable" note on failure instead of silent skip

### 2.8 — Validate GA4 Property IDs

**Affected files:** `components/sidebar.py`

**Problem:** Arbitrary text accepted as property ID, passed to GA4 retrieval. Invalid IDs get remote errors.

**Fix:**
- Validate `property_id.strip().isdigit()` before enabling pull button
- Show immediate error: "GA4 Property ID must contain digits only"
- Disable pull button while request is in progress

## Phase 4: Analytics Correctness 🟡

**Goal:** Fix analytics features that produce silently wrong or misleading results.

### 4.1 — Fix Forecasting Date Handling

**Affected files:** `utils/forecasting.py`

**Problem:** `np.arange(n)` treats row position as time regardless of actual date gaps.

**Fix:**
- Reindex to complete daily calendar
- Use elapsed days from first date: `(daily[date_col] - daily[date_col].min()).dt.days`
- Add explicit missing-day policy (fill with 0 for daily GA4, or flag sparse data)
- Validate `periods > 0`
- Convert `metric_col` with `pd.to_numeric(..., errors="coerce")` before aggregation

**Tests needed:** Irregular dates, missing days, nonnumeric metrics, negative projected values, constant series

### 4.2 — Fix Funnel Literal Matching

**Affected files:** `utils/funnels.py`

**Problem:** `str.contains()` uses regex by default. Paths with `?`, `.`, `+`, `[` can error or match wildly.

**Fix:**
- Use `regex=False` for literal substring matching
- Normalize steps (strip whitespace) before comparison
- Cap at 6-8 steps
- Validate metric column is numeric before aggregation
- Casefold for duplicate detection

**Tests needed:** Malformed regex characters, Unicode, empty df, missing columns, counts that increase between steps

### 4.3 — Fix Quality Outlier Counting

**Affected files:** `utils/data_loader.py`

**Problem:** Outliers counted per cell — one anomalous row affecting 3 metrics = 3 outliers.

**Fix:**
- Build boolean row mask: `outlier_mask |= z_scores.abs().gt(3).fillna(False)`
- Count unique rows: `int(outlier_mask.sum())`
- Rename "outliers" → "values to review" (spikes can be valid campaigns/seasonality)
- Separate file integrity from feature compatibility in grade calculation
- Don't penalize for missing expected columns (that's a feature-compatibility issue, not data quality)

### 4.4 — Stop Swallowing Chart Exceptions

**Affected files:** `utils/charts.py`

**Problem:** `except Exception: pass` converts every bug into "no chart."

**Fix:**
- Catch expected data errors narrowly: `KeyError, TypeError, ValueError`
- Log unexpected exceptions: `logger.exception()`
- Return `None` with a UI note: "A chart could not be generated for this dataset"

### 4.5 — Validate Chart Config Against DataFrame

**Affected files:** `utils/charts.py`

**Problem:** Chart config's selected dimension/metric/title are all ignored. Only `chart_type` is used.

**Fix:**
- Validate every requested column against `df.columns`
- Permit only approved chart types and aggregations
- Fall back with explicit notification when request can't be satisfied
- Or simplify contract: rename to "automatic default visualization" and drop the unused config params

### 4.6 — Fix Chart Hover Templates

**Affected files:** `utils/charts.py`

**Fix:** Use `<br>` and `<extra></extra>` for clean tooltips instead of concatenated labels
