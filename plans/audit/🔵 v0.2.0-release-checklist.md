## DataContext Gate (13 gates)

- [ ] **DC-01:** 3-layer model (`raw_df` → `base_df` → `active_df`) in `utils/data_context.py`
- [ ] **DC-02:** Content-based `source_id` — SHA-256 for uploads, canonical full-request fingerprint for GA4
- [ ] **DC-03:** GA4 request fingerprint includes every return-value-affecting field (dimension/metric filters, order-bys, limit, offset, timezone)
- [ ] **DC-04:** `with_custom_metrics` clears filters by default; `with_filters_cleared` restores from `base_df`
- [ ] **DC-05:** No-op transition behavior specified and tested (clear-when-clear, identical-filter, unchanged-metrics)
- [ ] **DC-06:** `data_context.py` and `test_data_context.py` conform to final 3-layer contract before writer migration begins
- [ ] **DC-07:** AST-based retired-key guard passes (catches attribute, subscript, `.get()`, `setdefault`, `pop`, `del`, membership, and chained-alias access)
- [ ] **DC-08:** Empty-filter result is an explicit empty `active_df` (not None)
- [ ] **DC-09:** `with_filtered_data` raises `ValueError` on None, `TypeError` on non-DataFrame, `ValueError` on empty descriptions
- [ ] **DC-10:** Cache functions include ALL output-affecting inputs (not just `source_id + version`); `frame_fingerprint` used instead of full DataFrames
- [ ] **DC-11:** Code/template version constants present for cached artifacts (`SUMMARY_PROMPT_SCHEMA_VERSION`, `QUALITY_RULESET_VERSION`, `FORECAST_SCHEMA_VERSION`)
- [ ] **DC-12:** All production analysis paths receive/use `DataContext`
- [ ] **DC-13:** Custom-metric, filter, clear/reload, forecast, funnel, summary, chart, export, and chat scenarios pass
