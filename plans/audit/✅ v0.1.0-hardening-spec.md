### 1.5 — Escape Exports (Centralized)

**Files:** Create shared helper in `utils/data_loader.py` (or new `utils/sanitize.py`). Apply in `utils/report_exporter.py` AND `utils/drive_client.py`.

**Shared helper (one source of truth for all spreadsheet-cell sanitization):**
```python
FORMULA_PREFIXES = ("=", "+", "-", "@")

def safe_spreadsheet_value(value: object) -> object:
    """Escape values that would be interpreted as formulas by Excel/Sheets.

    Spreadsheet programs interpret cells starting with =, +, -, or @ as
    formulas. This prefixes a single quote to render them as literal text
    without changing the displayed value. Also handles leading whitespace
    and control characters that may be trimmed before formula evaluation.
    """
    if not isinstance(value, str):
        return value
    stripped = value.lstrip("\t\r\n ")
    if stripped.startswith(FORMULA_PREFIXES):
        return "'" + value
    return value
```

**Apply to ALL spreadsheet-cell writing paths:**
- `build_excel_report()`: all DataFrame cells in Data sheet, summary lines in Dashboard sheet, Q&A cells (questions and answers), data source cell, column name headers
- `create_google_sheet()`: all Dashboard values, Data sheet cells, Q&A cells
- `write_dataframe_to_drive()`: all CSV-exported cell values

**Tests for ALL export paths:**

### Shared Helper: `active_dataframe()` with Defined Precedence

**Files:** `utils/session.py` (new helper)

Before the crash and filter fixes, add the shared helper. Define the explicit data-precedence contract so downstream features (summary, charts, forecasts, page-path aggregation, AI context) all use the same resolved DataFrame:

```text
raw_df                   → source upload/GA4 result
  → custom_metrics_df    → raw data plus validated derived metrics
  → filtered_df          → selected subset of custom-metric data
  → analysis_df          → filtered data if filters are active,
                            otherwise custom metrics if present,
                            otherwise raw data
```

Implementation:
```python
import pandas as pd
import streamlit as st

def active_dataframe() -> pd.DataFrame | None:
    """Return the analysis DataFrame respecting the full precedence chain.

    Precedence: filtered_df (if filters_active) > custom_metrics_df > raw df.
    Returns None if no data is loaded.
    """
    if st.session_state.get("filters_active") and st.session_state.get("filtered_df") is not None:
        return st.session_state.filtered_df
    custom_df = st.session_state.get("custom_metrics_df")
    if custom_df is not None:
        return custom_df
    return st.session_state.get("df")
```

**Preserves a valid empty DataFrame** when a filter yields zero rows (do NOT set `filtered_df = None` on zero-row filters). All downstream features — summary, charts, forecasts, page-path aggregation, AI context — call `active_dataframe()` instead of reading arbitrary `st.session_state` keys.

## Deferred Items (Post v0.1.0)

Create one GitHub issue per independently deliverable outcome below. Label each `post-v0.1.0` (optionally `v0.2.0` if sequencing matters, but do not treat `v0.2.0` as a delivery commitment). Link each issue from this section. In every issue, state why it is not a v0.1.0 release blocker, what would bring it back into scope, and concrete acceptance criteria.

### d1 — Rewrite Learn page for current componentized architecture

**Issue:** [#1](https://github.com/griffinkelton/insights-explorer/issues/1)
**Labels:** `documentation`, `post-v0.1.0`

**Why deferred:** Documentation polish; core disclosures (privacy, security, Drive removal) are corrected in v0.1.0 release docs. The Learn page is an educational resource, not a safety or correctness dependency.

**Would bring back into scope:** Discovery that the Learn page teaches actively unsafe patterns (e.g. obsolete OAuth flow, prompt-injection-as-code-fence-removal) that users are likely to copy into production code during the v0.1.0 window.

**Acceptance criteria:**
- Content reflects actual module boundaries (`components/`, `utils/`, `pages/`)
- Explains current data flows: upload → session → Gemini API, OAuth PKCE temp-file persistence
- Documents AI/GA4/Drive limitations honestly (Drive is export-only in v0.1.0)
- Removes all stale line-number references, obsolete architectural descriptions, and inaccurate test counts
- Teaches application-enforced security boundaries (not prompt injection via code-fence removal)
- Stale architecture structural tests updated or removed

### d2 — Refactor `styles.py` into named theme/layout constants

**Issue:** [#2](https://github.com/griffinkelton/insights-explorer/issues/2)
**Labels:** `maintenance`, `post-v0.1.0`

**Why deferred:** Maintainability improvement; current CSS works correctly. Not a safety, correctness, or disclosure dependency for v0.1.0.

**Would bring back into scope:** A Streamlit version update during the v0.1.0 hardening window that breaks the current CSS selectors, requiring a broader CSS restructure to fix.

**Acceptance criteria:**
- Split into named constants: `BASE_TOKENS_CSS`, `LIGHT_THEME_CSS`, `COMPONENT_CSS`, `LEARN_PAGE_CSS`, `ACCESSIBILITY_CSS`, `KEYBOARD_SHORTCUT_JS`
- No visual regressions; theme snapshot/smoke test passes in both dark and light modes
- No unescaped dynamic values enter unsafe HTML (reinforces v0.1.0 HTML safety baseline)
- Broad `div`/`span`/`[class*="css"]` selectors scoped or removed

### d3 — Design and implement Drive import (if Drive import returns)

**Issue:** [#3](https://github.com/griffinkelton/insights-explorer/issues/3)
**Labels:** `feature`, `post-v0.1.0`, `needs-design`

**Why deferred:** v0.1.0 removed Drive browsing for least-privilege security. Re-adding Drive import requires a deliberate design decision (Picker vs. direct listing, consent model, MIME-aware parsing) that should not be rushed into a hardening release.

**Would bring back into scope:** A validated user need for Drive-based data import that cannot be met by the existing file upload or GA4 pull paths during the v0.1.0 window.

**Acceptance criteria:**
- Picker/consent model designed and approved before any implementation
- Uses least-privilege access (prefer `drive.file` + Google Picker over `drive.readonly`)
- Supports MIME-aware parsing (CSV, XLSX, Google Sheets export) through the common validated ingestion path
- CSV/XLSX/Sheets parsing shares one validated byte-to-DataFrame path with local `load_file()`
- Formula escaping applied to all imported cell values
- Security and integration tests pass for each supported format

### d4 — Implement verified per-request Gemini context accounting

**Issue:** [#4](https://github.com/griffinkelton/insights-explorer/issues/4)
**Labels:** `observability`, `post-v0.1.0`

**Why deferred:** v0.1.0 removed the fabricated context meter (rows × columns × 2 heuristic). Re-adding a context meter requires verified per-request prompt-token data from Gemini usage metadata for both streaming and non-streaming calls, plus maintained per-model context-limit configuration. That observability infrastructure is not needed to make v0.1.0 safe or accurate.

**Would bring back into scope:** User confusion from the absence of any context indicator, or discovery that Gemini SDK reliably provides per-request input-token counts in a way that can be integrated without destabilizing the streaming path.

**Acceptance criteria:**
- Streaming and non-streaming usage metadata tested and confirmed reliable
- Model context-window limits are versioned in code (not hardcoded display strings)
- UI never estimates or displays fabricated usage as actual prompt-context data
- Context meter only shown when real per-request prompt-token data is available
- If usage metadata is unavailable for a request, display "Usage unavailable" rather than estimating

### d5 — Onboarding persistence

**Labels:** `ux`, `post-v0.1.0`

**Why deferred:** Current session-only tour state is functional and privacy-preserving. Persistence is a UX improvement, not a release blocker.

### d7 — DataContext refactor (immutable data lifecycle contract)

**Issue:** [#7](https://github.com/griffinkelton/insights-explorer/issues/7)
**Labels:** `architecture`, `post-v0.1.0`

**Why deferred:** Major architectural change. The v0.1.0 spec addresses the concrete symptoms (DataFrame crashes, stale caches, filter inconsistencies) with targeted fixes. A full `DataContext` refactor would expand scope significantly and should be designed deliberately post-release.

**Would bring back into scope:** Discovery that the targeted v0.1.0 fixes do not adequately prevent stale-state and filter-consistency regressions without the `DataContext` contract.

**Acceptance criteria:**
- Immutable `DataContext` dataclass with fields: `source_id` (content hash or GA4 query fingerprint), `version` (incremented on data/filter/metric changes), `raw_df`, `active_df` (custom metrics + filters applied), `filters`, `provenance`
- Every analysis function accepts `DataContext` explicitly rather than reading arbitrary `st.session_state` keys
- All cache keys derived from `source_id` + `version` + feature-specific parameters
- No regression in forecast, funnel, summary, or chart correctness after migration
