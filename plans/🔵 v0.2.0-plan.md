## Work Items

### 🏗️ Architecture

#### d7 — DataContext Refactor *(highest priority)*

- **Issue:** [#7](https://github.com/griffinkelton/insights-explorer/issues/7)
- **Effort:** 3–5 days
- **Why first:** Every other change touches data flow. An immutable `DataContext` contract eliminates the class of stale-state and filter-consistency bugs that v0.1.0 patched individually. After this, all analysis functions take `DataContext` explicitly instead of reading arbitrary `st.session_state` keys.
- **Key deliverables:**
  - `DataContext` dataclass: `source_id`, `version`, `raw_df`, `active_df`, `filters`, `provenance`
  - All cache keys derived from `source_id` + `version`
  - No direct reads from `st.session_state.df`, `custom_metrics_df`, or `filtered_df` in analysis functions — all go through `DataContext`
  - Scenario tests updated to assert correctness with DataContext (upload → filter → forecast/funnel → export)
  - No regression in forecast, funnel, summary, or chart correctness

### 📚 Documentation

#### d1 — Learn Page Rewrite

- **Issue:** [#1](https://github.com/griffinkelton/insights-explorer/issues/1)
- **Effort:** 2–3 hrs
- **Why:** Learn page content still reflects the old monolithic architecture, obsolete OAuth flow, and stale test counts. v0.1.0 fixed core disclosures; this brings the educational content up to date.
- **Key deliverables:**
  - Content reflects `components/`, `utils/`, `pages/` module boundaries
  - Documents current data flows and security boundaries
  - Includes a dedicated section summarizing the v0.1.0 security model: OAuth state, least-privilege scopes, export safety — with pointers to `SECURITY.md`
  - Avoids teaching unsafe patterns (prompt-injection hacks, "in-memory only" claims)
  - Removes stale line-number references and test counts

### 🧱 Maintenance

#### d2 — Refactor styles.py into Named Constants

- **Issue:** [#2](https://github.com/griffinkelton/insights-explorer/issues/2)
- **Effort:** 1–2 days
- **Why:** `styles.py` is ~500 lines of monolithic CSS/JS. Splitting into named constants improves maintainability without changing visual output.
- **Key deliverables:**
  - `BASE_TOKENS_CSS`, `LIGHT_THEME_CSS`, `COMPONENT_CSS`, `LEARN_PAGE_CSS`, `ACCESSIBILITY_CSS`, `KEYBOARD_SHORTCUT_JS`
  - No visual regressions in dark/light mode — verified via manual side-by-side check or DOM snapshot
  - Keyboard shortcut JS (`Cmd/Ctrl+K`) verified working after refactor
  - `VALID_THEMES` guard untouched
  - Broad CSS selectors scoped or removed

### 👁️ Observability

#### d4 — Verified Gemini Context Accounting

- **Issue:** [#4](https://github.com/griffinkelton/insights-explorer/issues/4)
- **Effort:** 1–2 days
- **Why:** v0.1.0 removed the fabricated context meter. Re-add only when reliable per-request prompt-token data is available from Gemini usage metadata.
- **Key deliverables:**
  - Streaming and non-streaming usage metadata confirmed reliable
  - Model context-limit configuration versioned in code
  - Expose only raw token counts and per-request limits; no derived "% of context used" metrics unless backed by tested static config
  - "Usage unavailable" shown when metadata is missing (never estimated)

### 🎨 UX

#### d5 — Onboarding Persistence

- **Issue:** [#5](https://github.com/griffinkelton/insights-explorer/issues/5)
- **Effort:** 1–2 hrs
- **Why:** Current tour is session-only. Persistence across browser sessions (via `localStorage`) prevents the tour from reappearing on every restart.
- **Key deliverables:**
  - Tour completion stored in `localStorage`
  - "Restart tour" control available

### ♿ Accessibility

#### d6 — `:focus-visible` Keyboard Styles

- **Issue:** [#6](https://github.com/griffinkelton/insights-explorer/issues/6)
- **Effort:** 1–2 hrs
- **Why:** Current hover states work but keyboard-only navigation has no visible focus indicators.
- **Key deliverables:**
  - Clear focus outline on all interactive elements
  - Works in both dark and light themes
  - Does not interfere with hover states

### 🔮 Feature (Design-Only)

#### d3 — Drive Import *(needs-design)*

- **Issue:** [#3](https://github.com/griffinkelton/insights-explorer/issues/3)
- **Effort:** Design phase only in v0.2.0; implementation deferred
- **Why:** v0.1.0 removed Drive browsing for least-privilege security. Re-adding requires deliberate design (Picker vs. direct listing, consent model, MIME-aware parsing).
- **Key deliverables (v0.2.0):**
  - Design document with approved architecture
  - Picker/consent model defined
  - **Security checklist:** acceptable scopes (prefer `drive.file`), consent UX, max file size/row limits, MIME filtering, privacy-copy updates
  - Explicit rationale for why Drive import remains safe relative to v0.1.0's least-privilege baseline
  - Acceptance criteria for implementation phase

## Recommended Execution Order

| Phase | Items | Rationale |
|-------|-------|-----------|
| **Phase 1** | d7 (DataContext) | Foundation — everything else builds on clean data contracts |
| **Phase 2** | d1 (Learn page), d5 (Onboarding) | Quick wins, improve user experience immediately |
| **Phase 3** | d2 (styles.py), d6 (focus-visible) | Maintenance + accessibility, no functional changes |
| **Phase 4** | d4 (context accounting) | Observability — requires Gemimi SDK metadata verification first |
| **Phase 5** | d3 (Drive import design) | Design-only; implementation deferred to v0.3.0 |

**Total effort:** ~10–16 days for Phase 1–4 implementation + Phase 5 design.

## Dependencies

- **d7 (DataContext)** is a hard prerequisite for any feature that reads `st.session_state` data — which is everything.
- **d1 (Learn page)** should follow d7 so it documents the current architecture accurately.
- **d2 (styles.py)** is independent of all other items.
- **d5 (onboarding)** and **d6 (focus-visible)** are independent and can be done in any order.
- **d4 (context accounting)** depends on Gemini SDK metadata reliability — requires research before implementation.
- **d3 (Drive import)** is design-only; no code dependencies.
