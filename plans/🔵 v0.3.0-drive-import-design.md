## Architecture Decision: Picker vs. Direct Listing API

**Decision: Use the Google Picker API.**

| Factor | Picker API | Direct listing (`drive.files.list`) |
|---|---|---|
| UX | Familiar Google file browser with search and preview | Custom-built file browser — significant UI effort |
| Consent scope | `drive.file` (existing v0.1.0 scope) — no expansion | `drive.readonly` — scope expansion, broader data exposure |
| File visibility | User explicitly selects each file | App can list all files — privacy concern |
| Maintenance | Google maintains the picker UI | App maintains a custom file browser indefinitely |

The Picker API avoids scope expansion, provides a polished UX, and keeps the app's Drive footprint minimal. The app never lists files the user hasn't explicitly selected.

### Transport decision

Phase 0 completed on 2026-07-31. Option A, a hidden-input bridge from
`st.components.v1.html()`, was **rejected** because the Picker executed in an
opaque `about:srcdoc` iframe and could not provide a reliable supported
transport (Google Picker returned 403 regardless of origin configuration).

The selected architecture is **Option B**: a repository-local declared
bidirectional Streamlit component. It uses the supported
`Streamlit.setComponentValue()` channel and is retained as a production
component for v0.3.0. See [`plans/00-sprints/✅ phase-0-debug-summary.md`](00-sprints/✅%20phase-0-debug-summary.md)
for the full decision record.

## Consent UX

1. **Button-first:** A "📂 Import from Drive" button appears in the sidebar (only when OAuth is valid). The picker iframe is NOT rendered passively — it requires an explicit click.
2. **Google Picker opens:** Filtered to spreadsheets, CSVs, and XLSX. User selects a file.
3. **Server-side download:** The file ID is the only accepted opaque value from the Picker. Name, MIME type, and size are fetched authoritatively from the Drive API server-side.
4. **Ingestion:** Downloaded bytes flow through the existing `data_loader.load_file()` pipeline (same validation, row limits, and truncation as uploads). A `DataContext` is created with `"drive-import:{filename}"` provenance.

## Security Model

### Scopes

- **Reuses `drive.file`** — no scope expansion. The app already requests this for exports.
- **AST guard extended** — rejects `drive`, `drive.readonly`, and `drive.metadata.readonly` in runtime source.

### Token safety

- OAuth token passed only as a declared-component runtime argument after explicit user action — never embedded in HTML.
- Token never appears in logs, user-facing errors, or visible UI.
- Component never returns the token, API key, or Picker metadata to Python.
- Component only rendered after explicit user click — not passive.

### File safety

- **3-layer size validation:** metadata preflight + bounded writer (rejects writes exceeding 100 MB) + final `len()` check.
- **Server metadata authority:** Picker client `name`/`mimeType` are untrusted. `files.get(fields=…)` is authoritative.
- **Zero-byte rejection** in `download_drive_file()` — clear error before context creation.
- **No disk writes:** All bytes in memory (`BytesIO`).
- **Google Sheets:** Exported as CSV via `files.export_media()` — first sheet only (documented in UX copy).
- **Same limits as uploads:** 100 MB / 50,000 rows.

### Privacy copy

> The app does not list your Drive. You choose a file in Google's Picker, and the app accesses the selected file to import it. The file is processed in memory and never stored to disk.

## v0.1.0 Baseline Preservation

| Principle | Preserved by |
|---|---|
| Least-privilege scopes | Reuses `drive.file` — no expansion |
| Session-only tokens | OAuth flow unchanged |
| AST scope guards | Extended to reject 3 broader Drive scopes |
| Zero file persistence | BytesIO, no disk writes |
| Content-derived identity | SHA-256 of bytes, `"drive:"` prefix |
| Clear Data semantics | Identical to uploads |
| Error redaction | Classified messages, no raw API/token leakage |

## Acceptance Criteria (summary)

Full per-phase gates in the implementation spec. High-level criteria:

- [ ] Google Picker opens on explicit button click, filters correctly
- [ ] File ID reliably reaches Python (transport proven in Phase 0)
- [ ] Server-side download with 3-layer size validation
- [ ] DataContext created with drive provenance
- [ ] 100 MB / 50k row limits enforced
- [ ] Clear Data removes drive context
- [ ] No scope expansion; AST guard passes
- [ ] No OAuth token, API key, file ID, Picker metadata, or raw error leaks to application-controlled UI, logs, exceptions, or persisted state
- [ ] No bytes written to disk; no file IDs persisted
- [ ] Privacy copy present in sidebar, README, and Learn page
- [ ] Full suite passes
