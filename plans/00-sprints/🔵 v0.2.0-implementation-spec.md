## Design Decisions

| # | Decision | Rationale |
|---|---|---|
| D1 | DataContext is a **frozen dataclass with 3-layer DataFrame model** (`raw_df` → `base_df` → `active_df`) | Prevents accidental mutation. `base_df` holds the unfiltered analytical dataset (including custom metrics); clearing filters restores from `base_df`, not `raw_df`. All transitions produce a NEW instance via `dataclasses.replace()`. Shallow-immutable only — DataFrames must not be mutated in-place. |
| D2 | `active_dataframe()` is **replaced entirely** | `DataContext.active_df` is the single source of truth. Temporary migration wrapper permitted mid-d7, deleted at completion. |
| D3 | Migration is **incremental without deprecation** (short-lived migration bridge) | 4-step sequence: introduce + test → migrate writers (dual-write to old + new keys) → migrate readers by vertical slice → remove legacy keys + add AST-based static guard. No long-lived dual-state period. The interim dual-write is a bridge, not a permanent compatibility layer. |
| D4 | **Analysis-versioned logical invalidation** with explicit cache inputs | `source_id + version` in all `@st.cache_data` keys. Version increments on every analysis-relevant transition. Never rely on `st.cache_data.clear()` as routine mechanism. **Critically: `source_id + version` is a namespace prefix, not a substitute for the full functional input signature.** Every cached function must accept all output-affecting inputs as explicit arguments. |
| D5 | Old keys **removed at end of d7** | `df`, `filtered_df`, `custom_metrics_df`, `filters_active`, `ga4_truncated` deleted from `app.py`. AST-based static guard prevents reintroduction (catches attribute reads, subscript reads, `.get()`, and aliases — not just string matches). UI-only state preserved. |
| D6 | Learn page: **full restructure** | 8-section learner's journey (not module boundaries). Progressive pattern: concept → example → excerpt → try it → check yourself. Code excerpts ≤ 20 lines. |
| D7 | Styles refactor: **extract JS too** | `THEME_SYNC_JS`, `KEYBOARD_SHORTCUTS_JS` become named constants. Fix discoverability, editable-field safety, and listener-guard order. |
| D8 | Styles testing: **pytest + manual hybrid** | Pytest for structural assertions. Manual visual acceptance across 8 states. No DOM screenshots in v0.2.0. |
| D9 | Focus-visible: **dedicated variables aliased from accent** | `--focus-ring-color: var(--accent)`, plus width, offset, soft variants. Never use red/destructive colors. |
| D10 | Onboarding: **frontend-owned or bidirectional custom component** | `st.markdown(..., unsafe_allow_html=True)` JS injection is unreliable in Streamlit — JS may be stripped. Use a Streamlit custom component or `st.html()` after proof-of-concept. Versioned localStorage key `ga4_insight_explorer.onboarding.v1.completed`. "Replay tour" + "Skip" controls. No `session_state` fallback. |
| D11 | Gemini context: **informational only** | Provider-reported counts: input, output, thought, cached, tool-use, total. `countTokens` only for concrete guard. No gauges, traffic lights, or warnings. |
| D12 | Phase 2 + Phase 3: **parallel OK** | Isolated branches, agreed-upon semantic class names, short final integration/visual QA pass. |
| D13 | Release gate: **custom lightweight checklist** | `plans/audit/v0.2.0-release-checklist.md` with 15 binary gates across 4 categories. Formal enough to prevent regressions, lighter than v0.1.0. |

### 1.1 DataContext Dataclass

Create/revise `utils/data_context.py`:

```python
from dataclasses import dataclass, replace
from typing import NamedTuple
import pandas as pd


class FilterState(NamedTuple):
    """Immutable description of active filters."""

    descriptions: tuple[str, ...] = ()
    is_active: bool = False
    row_count: int = 0  # Must equal len(active_df). 0 means empty result (valid, not None).


@dataclass(frozen=True)
class DataContext:
    """Immutable data lifecycle contract — 3-layer DataFrame model.

    LAYER MODEL:
        raw_df   — Original loaded upload or GA4 result. Never filtered, never
                   mutated in place. The immutable ground truth.
        base_df  — Current unfiltered analytical dataset. Initially a copy of
                   raw_df. After custom metrics, becomes the custom-metric output.
                   This is what "clear filters" restores to.
        active_df — The currently analyzed dataset. When filters are active:
                   filtered base_df. When filters are clear: same as base_df.

    IMPORTANT: frozen=True is shallow only. DataFrames inside are still
    mutable. The invariant is: NO code may mutate raw_df, base_df, or active_df
    in place. Transformations create new DataFrames and return a replacement
    DataContext via dataclasses.replace().
    """

    source_id: str         # Content-derived: "file:{sha256[:16]}" or "ga4:{sha256[:16]}"
    version: int           # Monotonic — incremented on every analysis-relevant transition
    raw_df: pd.DataFrame   # Original loaded data (never modified after creation)
    base_df: pd.DataFrame  # Unfiltered analytical base (custom metrics modify this)
    active_df: pd.DataFrame  # Current analysis surface (filtered base_df, or base_df when no filters)
    filters: FilterState = FilterState()
    provenance: tuple[str, ...] = ()  # Human-readable history
    truncated: bool = False  # True if GA4 500k cap was hit

    @property
    def cache_key(self) -> str:
        """Stable cache namespace prefix: source_id + version.

        Note: This is a namespace prefix. Cached functions must also include
        ALL output-affecting parameters as explicit arguments — see §1.6.
        """
        return f"{self.source_id}:v{self.version}"
```

**Required invariants:**

- `raw_df` is the original loaded upload or GA4 result. It is **never** filtered or mutated in place.
- `base_df` is the current **unfiltered** analytical dataset. Initially it is a copy of `raw_df`; after custom metrics are applied, it becomes the custom-metric output.
- `active_df` is the currently **analyzed** dataset: filtered `base_df` when filters are active, otherwise `base_df`.
- `frozen=True` provides shallow immutability only; transformations must copy input frames and return a new context with `replace()`.
- `FilterState.row_count` **must** equal `len(active_df)`, either derived or validated in the transition function.
- `None` is **never** a valid filtered DataFrame. An empty DataFrame is the valid "no results" state.

### 1.2 Factory Functions

**Upload identity** — use a digest of the original uploaded **bytes**, not the filename:

```python
import hashlib

def create_context_from_upload(
    df: pd.DataFrame,
    file_bytes: bytes,
    display_name: str = "",
) -> DataContext:
    """Create a DataContext from uploaded file bytes.

    Uses SHA-256 of file content for source_id — same bytes = same ID,
    different bytes = different ID regardless of filename.

    Args:
        df: Validated DataFrame from data_loader.
        file_bytes: Raw file bytes (for content-derived source_id).
        display_name: Human-readable filename stored in provenance, not cache key.

    Returns:
        DataContext with version=0.
    """
    content_hash = hashlib.sha256(file_bytes).hexdigest()[:16]
    base = df.copy()
    return DataContext(
        source_id=f"file:{content_hash}",
        version=0,
        raw_df=df.copy(),
        base_df=base,
        active_df=base.copy(),
        provenance=(f"uploaded:{display_name}",) if display_name else ("uploaded",),
    )
```

**GA4 identity** — use a deterministic fingerprint of the **canonical full GA4 request**, not just the property ID:

```python
import json

def create_context_from_ga4(
    df: pd.DataFrame,
    property_id: str,
    date_range: tuple[str, str],
    dimensions: list[str],
    metrics: list[str],
    truncated: bool = False,
) -> DataContext:
    """Create a DataContext from a GA4 data pull.

    Uses SHA-256 of the canonical request fingerprint for source_id.
    Two pulls of the same property with different date ranges, dimensions,
    or metrics produce distinct source_ids. Identical requests get the
    same source_id, enabling legitimate cache reuse.

    Args:
        df: DataFrame returned by ga4_client.pull_ga4_report().
        property_id: GA4 property identifier.
        date_range: (start_date, end_date) tuple.
        dimensions: List of dimension names requested.
        metrics: List of metric names requested.
        truncated: True if the 500k row cap was hit.

    Returns:
        DataContext with version=0 and truncated flag set appropriately.
    """
    # Canonical request fingerprint — sorted for determinism
    request = {
        "property_id": property_id,
        "date_range": list(date_range),
        "dimensions": sorted(dimensions),
        "metrics": sorted(metrics),
    }
    canonical = json.dumps(request, sort_keys=True)
    request_hash = hashlib.sha256(canonical.encode()).hexdigest()[:16]

    base = df.copy()
    return DataContext(
        source_id=f"ga4:{request_hash}",
        version=0,
        raw_df=df.copy(),
        base_df=base,
        active_df=base.copy(),
        provenance=(f"ga4-pull:{property_id}",),
        truncated=truncated,
    )
```

**Design rationale for content-based IDs:**

- A random UUID prevents accidental cache sharing but also forfeits legitimate reuse for an identical request.
- A filename-based ID (`file:Q3_report.csv`) collides when the same filename contains different data.
- A property-ID-only GA4 ID collides when different date ranges/metrics are pulled.
- Content fingerprints give correctness (same data = same cache hit, different data = different cache miss).
- Optionally record a pull/run ID in `provenance` for auditability without polluting the cache namespace.

### 1.3 Transition Functions (return new DataContext)

```python
def with_custom_metrics(
    context: DataContext,
    metrics_df: pd.DataFrame,
) -> DataContext:
    """Replace the analytical base and clear filters by default.

    Custom metrics change the schema/derived values. Prior filters may not be
    meaningful against the new columns. Clearing filters is the safe default;
    reapply_filters() is a separate, explicit path if needed later.

    Args:
        context: Existing DataContext.
        metrics_df: DataFrame with custom metric columns added.

    Returns:
        New DataContext with base_df replaced, active_df reset, filters cleared.

    Raises:
        ValueError: if metrics_df is None.
    """
    if metrics_df is None:
        raise ValueError("metrics_df must be a DataFrame")

    base_df = metrics_df.copy()
    return replace(
        context,
        version=context.version + 1,
        base_df=base_df,
        active_df=base_df.copy(),
        filters=FilterState(),
        provenance=(*context.provenance, "custom-metrics-applied"),
    )


def with_filtered_data(
    context: DataContext,
    filtered_df: pd.DataFrame,
    descriptions: tuple[str, ...],
) -> DataContext:
    """Set the filtered active dataset. Zero rows are valid and preserved.

    Args:
        context: Existing DataContext.
        filtered_df: Filtered DataFrame (may be empty with 0 rows).
        descriptions: Human-readable filter descriptions for FilterState.

    Returns:
        New DataContext with active_df set, filters recorded, version bumped.

    Raises:
        ValueError: if filtered_df is None (empty DataFrame is OK, None is not).
    """
    if filtered_df is None:
        raise ValueError("filtered_df must be a DataFrame, not None")

    active_df = filtered_df.copy()
    return replace(
        context,
        version=context.version + 1,
        active_df=active_df,
        filters=FilterState(
            descriptions=descriptions,
            is_active=True,
            row_count=len(active_df),
        ),
        provenance=(*context.provenance, "filters-applied"),
    )


def with_filters_cleared(context: DataContext) -> DataContext:
    """Restore the current unfiltered analytical base.

    Restores active_df from base_df (NOT raw_df) — this preserves custom metrics
    that were applied before filtering.

    Returns:
        New DataContext with active_df restored, filters cleared, version bumped.
    """
    return replace(
        context,
        version=context.version + 1,
        active_df=context.base_df.copy(),
        filters=FilterState(),
        provenance=(*context.provenance, "filters-cleared"),
    )
```

**Key semantic differences from the original 2-layer design:**

| Scenario | Old (2-layer) | New (3-layer) |
|---|---|---|
| Apply custom metrics → clear filters | `active_df` reverts to `raw_df` (loses custom metrics!) | `active_df` restores from `base_df` (custom metrics preserved) |
| Apply custom metrics after filters | Filters preserved (may be stale against new columns) | Filters cleared by default (safe) |
| `with_filtered_data(None)` | Allowed `None` to pass through | Raises `ValueError` (explicit contract) |
| `FilterState.row_count` | Set but not validated | Must equal `len(active_df)` |

### 1.5 Migration Plan (4 Steps, Self-Contained Commits)

**Verify after each commit:** `pytest tests/ -q` — all tests must pass.

The migration uses a **short-lived migration bridge**: writers dual-write to both `data_context` and the old keys, readers read from old keys while being migrated one by one, and at the end all old keys are removed. This is a bridge, not a permanent compatibility layer — it lasts only as long as it takes to migrate all readers (ideally one session, not a release cycle).

**Why AST-based, not text scan:** A text scan misses valid-but-forbidden access patterns:

```python
st.session_state["df"]           # subscript read
st.session_state.get("filtered_df")  # .get() pattern
state = st.session_state; state.df   # alias access
state.get("custom_metrics_df")       # alias + .get()
```

The AST guard must detect:
- **Attribute reads:** `st.session_state.df`
- **Subscription reads/writes:** `st.session_state["df"]`
- **`.get()` patterns:** `st.session_state.get("df")`, `st.session_state.get("filtered_df", ...)`
- **Aliases:** any variable assigned from `st.session_state` and subsequently used to access retired keys

The guard should scan all production modules (`utils/`, `components/`, `pages/`, `app.py`) while excluding tests, fixtures, generated assets, and planning/documentation files.

Retired keys checked: `df`, `filtered_df`, `custom_metrics_df`, `filters_active`, `ga4_truncated`.

### 1.6 Cache Key Strategy

**Two rules, both mandatory:**

1. **Versioned keys make stale results unreachable by design.** Never use `st.cache_data.clear()` as the routine invalidation mechanism.
2. **`source_id + version` is a namespace prefix — not a substitute for the full functional input signature.** Every cached function must accept ALL output-affecting inputs as explicit arguments.

**Why rule 2 matters:** If `build_summary_prompt(source_id, version, active_df, stats)` caches on `(source_id, version)` alone, changing `stats` or the prompt template won't invalidate the cache — the function returns stale output even though the data changed. The version bumps on data transitions, but other inputs (model selection, filter descriptions, truncation state) also affect output.

**Cache policy by artifact:**

| Cached artifact | Required key inputs |
|---|---|
| Summary/prompt | `source_id`, `version`, model, prompt template/options, selected columns, truncation state |
| Chart aggregation | `source_id`, `version`, chart type/configuration, dimension, metric, date range, sort/limit |
| Forecast | `source_id`, `version`, date column, metric column, horizon, aggregation/frequency, model options |
| Funnel/page-path | `source_id`, `version`, path column, metric, step count, sorting/aggregation options |
| Gemini result (if cached later) | `source_id`, `version`, model, normalized prompt, relevant context options, explicit user opt-in |
| Upload parse / quality report | content-derived source identity + parser/quality-rule version |

**Example of correct cache decoration:**

```python
@st.cache_data
def build_summary_prompt(
    source_id: str,
    analysis_version: int,
    active_df: pd.DataFrame,
    stats: dict,
    model: str,
    truncation_note: bool,
) -> str:
    ...
```

The function signature makes every cache-invalidating input explicit. Streamlit's cache hasher will detect changes to any argument and recompute as needed.

**Guard tests:**
- AST guard catches attribute reads (`st.session_state.df`).
- AST guard catches subscript reads (`st.session_state["df"]`).
- AST guard catches `.get()` patterns.

### 2.2 Onboarding Persistence (d5)

**Current state:** Tour is session-only. Browser restart re-shows tour.

**⚠️ Revision note:** The original spec proposed injecting JavaScript through `st.markdown(..., unsafe_allow_html=True)`. Streamlit guidance indicates this may be stripped or not executed. The supported paths are custom components (for JavaScript behavior with Python-side state) or `st.html()` (after proof-of-concept validation).

**Choose one implementation model:**

| Option | Recommendation | Design |
|---|---|---|
| **Frontend-owned tour** | Preferred if the tour is purely visual | A custom component owns tour visibility, progression, `localStorage`, Skip, Replay, and completion |
| **Bidirectional custom component** | Preferred if Streamlit needs tour state | The component reads/writes versioned localStorage and sends `completed`, `skipped`, or `replay` state to Python |
| **`st.html()` JavaScript** | Only after a proof-of-concept | It can execute JavaScript when explicitly enabled, but still needs a reliable state bridge into Python |

**Behavioral requirements (implementation-agnostic):**

- Versioned localStorage key: `ga4_insight_explorer.onboarding.v1.completed` (allows redesigned tour to reappear after a future release without server migration logic)
- **Skip** button writes the completion flag (same as completing the tour)
- **Replay tour** control clears the completion flag and restarts the tour
- Clearing browser storage safely shows the tour again
- No `session_state` fallback — single source of truth in browser persistence
- Versioning lets a materially redesigned onboarding sequence intentionally reappear

**Pre-implementation proof-of-concept checklist:**
- [ ] Completion survives browser refresh
- [ ] Completion survives a new browser session (close and reopen)
- [ ] Replay works

def build_theme_css(theme: str) -> str:
    """Assemble CSS + JS for the given theme. Only validated theme is interpolated."""
    if theme not in VALID_THEMES:
        raise ValueError(f"Unknown theme '{theme}'. Valid themes: {sorted(VALID_THEMES)}")
    theme_div = f'<div id="theme-data" data-theme="{theme}" style="display:none;"></div>'

        f"{LEARN_PAGE_CSS}\n{ACCESSIBILITY_CSS}\n</style>\n"

```python
def _track_usage(response) -> dict | None:
    """Extract provider-reported usage metadata. Returns None if unavailable."""
    usage = getattr(response, "usage_metadata", None)
    if usage is None:
        return None
    return {
        "prompt_tokens": getattr(usage, "prompt_token_count", 0) or 0,
        "output_tokens": getattr(usage, "candidates_token_count", 0) or 0,
        "thought_tokens": getattr(usage, "thoughts_token_count", 0) or 0,
        "cached_tokens": getattr(usage, "cached_content_token_count", 0) or 0,
        "tool_tokens": getattr(usage, "tool_use_token_count", 0) or 0,
        "total_tokens": getattr(usage, "total_token_count", 0) or 0,
    }
```
