# v0.3.0 — Drive Import Implementation Spec

> **Based on:** `plans/🔵 v0.3.0-drive-import-design.md` (architecture decisions)
> **Status:** 🔵 Spec'd — not yet implemented
> **Effort:** 5 phases (0–4), ~5-7 days
>
> **⚠️ Phase 0 is a mandatory proof-of-concept gate.** The picker-to-Python transport must be proven in the deployed target environment before any Phase 1–4 code is written. If Phase 0 fails, the transport mechanism changes to a declared bidirectional Streamlit custom component — do not patch the hidden-input bridge.

---

## Design Decisions

| # | Decision | Rationale |
|---|---|---|
| **D1** | Google Picker API over `drive.files.list` | Avoids scope expansion; picker uses existing `drive.file` scope; user explicitly selects each file |
| **D2** | Picker rendered via iframe; transport mechanism decided by Phase 0 spike | `st.components.v1.html()` is an embedding primitive with no supported bidirectional value-return channel. Phase 0 proves whether a simple bridge works; if not, fall back to a declared bidirectional component |
| **D3** | OAuth token injected via `json.dumps()` into `<script type="application/json">`, never string-replaced into JS | Prevents injection; avoids logging; JSON serialization handles escaping automatically |
| **D4** | Picker rendered on-demand (button-first UX), not passively because credentials exist | Reduces token-bearing iframe exposure; user explicitly initiates import |
| **D5** | `files.export` for Google Sheets, `files.get_media` for CSVs/XLSX | Google Sheets have no binary download via `files.get` — must export to CSV/XLSX |
| **D6** | Server-side metadata authority — ignore picker `name`/`mimeType`, fetch via `files.get(…fields=…)` | Client payload is untrusted; server metadata is authoritative for MIME allowlisting, filename, and size |
| **D7** | 3-layer file-size validation: metadata preflight + streamed byte cap + final `len()` check | Metadata `size` is unreliable for native Google Sheets; streamed byte cap prevents OOM; final check is a safety net |
| **D8** | Reuse existing `data_loader.load_file()` pipeline | Avoids duplicating validation, size checks, row limits, and truncation logic |
| **D9** | New `create_context_from_drive()` factory | Provenance distinguishes drive-import from upload: `"drive-import:{filename}"` vs `"upload:{filename}"` |
| **D10** | Google Picker requires a developer key (API key) in addition to the OAuth token | Picker documentation specifies `.setDeveloperKey()`; read from `st.secrets["GOOGLE_API_KEY"]` |
| **D11** | Zero-byte files rejected in `download_drive_file()`, not deferred to context factory | User-facing error at download time is clearer; context factory requires non-empty bytes |

## Phase 0: Picker Transport Proof of Concept (Mandatory Gate)

**Effort:** 2-4 hours | **Prerequisite:** Nothing | **Blocks:** Phase 3 (UI integration)

**Goal:** Prove that a file ID selected in the Google Picker reliably reaches Python, survives reruns, and does not throw cross-origin or DOM-access errors. Do not build the full feature — build only the transport.

### 0.1 Spike scope

Create a minimal Streamlit page or sidebar section that:

1. Renders a Google Picker via `st.components.v1.html()` (or a declared component if the simple bridge fails)
2. Filters to CSV, XLSX, and Google Sheets MIME types
3. Passes the OAuth token securely (JSON-encoded, not string-replaced)
4. Passes the developer key from `st.secrets`
5. On file selection, sends an opaque payload `{fileId, name, mimeType}` to Python
6. Python receives the payload, logs a redacted success message (no token, no raw file ID in user-facing output), and displays the selected filename

### 0.2 Transport mechanisms to test (in priority order)

#### Option A: Hidden `st.text_input` DOM bridge

The picker iframe uses `window.parent.document.querySelector('input[aria-label="_drive_picker_bridge"]')` and `nativeInputValueSetter` to set the value and dispatch an `input` event. Streamlit detects the change and reruns.

**Risks:** Same-origin policy, iframe sandboxing, Streamlit internal DOM/ARIA instability.

**Passes if:**
- A dummy payload `{fileId: "test", name: "test.csv"}` reaches `st.session_state._drive_picker_bridge`
- Works in Chrome, Safari, and Firefox (no Cross-Origin errors, no `DOMException`)
- Survives 3 consecutive selections (no stale state)
- Cancel does not trigger import
- Survives dark/light theme changes
- No OAuth token, file ID, or raw API error appears in application-controlled visible UI, application logs, localStorage, or application-generated browser-console output

**If Option A fails for any browser:** Fall back to Option B. Do not add increasingly complex DOM selectors, `postMessage` patches, session-state mirrors, or browser-specific hacks.

#### Option B: Declared bidirectional Streamlit custom component

Use `st.components.v1.declare_component(name, path="components/drive_picker/")` pointing to a directory with:

```
components/drive_picker/
  index.html          # Picker HTML/JS
  streamlit-component-lib.js  # Official Streamlit component library
```

The component calls `Streamlit.setComponentValue({fileId, name, mimeType})` in the picker callback. Python receives the value from `drive_picker_component(key="drive_picker")`.

**Passes if:** All Option A criteria pass, plus:
- `Streamlit.setComponentValue` triggers a rerun with the correct value
- Repeated selections work (nonce-based or value-change detection)
- Component renders correctly in both themes

### 1.2 Drive download function (`utils/drive_client.py`)

```python
import io
from googleapiclient.http import MediaIoBaseDownload

# Supported MIME types for Drive import
DRIVE_IMPORT_MIME_TYPES = {
    "text/csv": ".csv",
    "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet": ".xlsx",
    "application/vnd.google-apps.spreadsheet": ".csv",
}

MAX_DRIVE_IMPORT_BYTES = 100 * 1024 * 1024  # 100 MB

GOOGLE_SHEETS_EXPORT_MIME = "text/csv"


def download_drive_file(
    credentials: Credentials,
    file_id: str,
) -> tuple[bytes, str]:
    """Download a file from Google Drive for import.

    Server-side metadata is authoritative — the file_id is an opaque
    token from the Picker; name, MIME type, and size are fetched from
    the Drive API, not from client-provided values.

    Size validation uses 3 layers:
    1. Metadata preflight — reject if 'size' field > 100 MB (fast).
    2. Streamed byte cap — hard-abort the download/export stream if
       accumulated bytes exceed 100 MB (catches Sheets with no preflight).
    3. Final check — verify len(bytes) ≤ 100 MB before returning.

    Zero-byte files are rejected with a clear user-facing error.

    Args:
        credentials: Valid OAuth credentials (with drive.file scope).
        file_id: Google Drive file ID from the Picker.

    Returns:
        Tuple of (file_bytes, normalized_filename).
        - Google Sheets: filename gets '.csv' extension if not already present.
        - CSV/XLSX: filename used as-is from server metadata.

    Raises:
        ValueError: If file is empty, exceeds 100 MB, or has unsupported MIME.
        RuntimeError: If the Drive API returns an error (404, 403, etc.).
    """
    ...
```

**Implementation details:**

1. **Fetch server metadata** — `files.get(fileId=file_id, fields='name,mimeType,size')`. Use the returned values for validation. Do NOT trust the Picker payload's `name` or `mimeType`.

2. **MIME allowlist** — only `DRIVE_IMPORT_MIME_TYPES` keys are permitted. Reject anything else with a clear user error.

3. **3-layer size validation:**
   - **Layer 1 (metadata preflight):** If the metadata `size` field is present and > `MAX_DRIVE_IMPORT_BYTES`, raise `ValueError` immediately. This handles CSVs and XLSXs. Note: Google Sheets metadata may omit or misrepresent the byte size — this is only a fast path.
   - **Layer 2 (streamed byte cap):** For `files.export_media()` (Google Sheets), use chunked download via `MediaIoBaseDownload` into a bounded writer whose `write()` rejects any write that would exceed the cap:
     ```python
     import io

     class _BoundedBytesIO(io.BytesIO):
         """BytesIO that rejects writes exceeding MAX_DRIVE_IMPORT_BYTES.

         Rejects the chunk before it is retained in the in-memory output
         buffer, preventing unbounded accumulation from a large Google
         Sheets export that lacks a metadata size.
         """
         def write(self, data: bytes) -> int:
             if self.tell() + len(data) > MAX_DRIVE_IMPORT_BYTES:
                 raise ValueError(
                     "The selected file exceeds the 100 MB limit."
                 )
             return super().write(data)
     ```
     This preserves the hard-cap intent for native Google Sheets exports instead of merely detecting oversize after buffer growth.
   - **Layer 3 (final check):** After download, verify `len(file_bytes) <= MAX_DRIVE_IMPORT_BYTES` before returning. Safety net.

4. **Zero-byte rejection:** If `file_bytes` is empty after download, raise `ValueError("The selected file is empty.")`. Do not defer this to `create_context_from_drive()`.

5. **Google Sheets filename:** `files.export` exports the first sheet only. Build the filename as:
   ```python
   if name.lower().endswith('.csv'):
       final_name = name
   else:
       final_name = f"{name}.csv"
   ```
   This avoids `report.csv.csv` when the Sheet is already named `report.csv`.

6. **Google Sheets product behavior:** The returned CSV contains only the **first sheet** of the workbook. This must be stated in user-facing copy (sidebar, error messages, Learn page). Do not claim or imply multi-sheet import.

7. **Error handling:** Wrap all Drive API calls in try/except `HttpError`. Classify errors:
   - 404 → `RuntimeError("File not found or access denied. Check that you have permission.")`
   - 403 → `RuntimeError("Access denied. Try reconnecting your Google account.")`
   - Other → `RuntimeError("Could not download the file. Please try again.")`
   - Never expose raw API errors, file IDs, or token fragments in exception messages.
   - **Structured logging only:** Log an allowlisted error category/status code, never the raw `HttpError` text, request URL, file ID, or full exception representation. Do NOT use `exc_info=True` in Drive error handlers — exception tracebacks can reproduce the raw error payload including request URLs.

8. **Token refresh:** Use the existing `_build_drive_service()` pattern — `credentials.refresh(Request())` if expired.

9. **No disk writes:** All bytes stay in memory (`BytesIO`). Never call `.write()` to a filesystem path.

### 2.1 Drive Context factory (`utils/data_context.py`)

```python
def create_context_from_drive(
    df: pd.DataFrame,
    file_bytes: bytes,
    display_name: str = "",
) -> DataContext:
    """Create a DataContext from a Google Drive import.

    Identical to create_context_from_upload in mechanics, but sets
    provenance to "drive-import:{name}" (vs "upload:{name}") and
    source_id prefix to "drive:" (vs "file:").

    Callers MUST ensure file_bytes is non-empty — download_drive_file()
    rejects zero-byte files before this factory is reached.

    Raises:
        TypeError: if df is not a pandas DataFrame.
        ValueError: if file_bytes is empty or not bytes.
    """
    if not isinstance(df, pd.DataFrame):
        raise TypeError("df must be a pandas DataFrame")
    if not isinstance(file_bytes, bytes) or not file_bytes:
        raise ValueError("file_bytes must be non-empty bytes")

    content_hash = hashlib.sha256(file_bytes).hexdigest()[:24]
    base = df.copy(deep=True)
    return DataContext(
        source_id=f"drive:{content_hash}",
        version=0,
        raw_df=df.copy(deep=True),
        base_df=base,
        active_df=base.copy(deep=True),
        provenance=(f"drive-import:{display_name}",) if display_name else ("drive-import:unknown",),
    )
```

### 3.1 Token-safe HTML generation

The picker HTML/JS must use **JSON serialization**, never string replacement. `json.dumps()` safely escapes JavaScript-string content, but it does NOT protect against `</script>` terminating the `<script>` element. Use a dedicated encoder:

```python
import json

def _json_for_script(value: object) -> str:
    """Serialize for safe embedding inside <script type="application/json">.

    Replaces '<' with \\u003c so that '</script>' (or any '</' sequence)
    cannot terminate the enclosing element, regardless of token content.
    """
    return json.dumps(value, ensure_ascii=False).replace("<", "\\u003c")


def _picker_html(oauth_token: str, developer_key: str) -> str:
    """Build picker HTML with JSON-serialized configuration."""
    config = {
        "oauthToken": oauth_token,
        "developerKey": developer_key,
        "mimeTypes": [
            "application/vnd.google-apps.spreadsheet",
            "text/csv",
            "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
        ],
    }
    config_json = _json_for_script(config)

    return f"""<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <script src="https://apis.google.com/js/api.js"></script>
  <style>
    /* minimal button + status styles */
  </style>
</head>
<body>
<div id="root"></div>
<script id="picker-config" type="application/json">
  {config_json}
</script>
<script>
  const config = JSON.parse(
    document.getElementById('picker-config').textContent
  );
  // Use config.oauthToken, config.developerKey, config.mimeTypes
  ...
</script>
</body>
</html>"""
```

**Required test:** A value containing `</script><script>alert(1)</script>` must produce HTML that, when parsed, creates only one `<script>` node. The second `</script>` must be unreachable as a closing tag — `\\u003c` ensures it remains inert text.

**Rules:**
- Token never appears in a `const OAUTH_TOKEN = "..."` string literal
- Token never passed through `.replace("__TOKEN__", ...)`
- `_json_for_script()` escapes `<` to `\\u003c` — prevents `</script>` injection
- Never log the rendered HTML, config payload, or any intermediate string containing the token
- The configuration JSON must be parsed only after the trusted Picker library (`gapi.load('picker', …)`) has loaded. Do not interpolate configuration values into executable JavaScript
- The picker callback may return `{fileId, name, mimeType}`, but only `fileId` may be passed to server-side ingestion (§3.4)

def _render_drive_import() -> None:
    if st.session_state.ga4_creds is None:

    except Exception:

### 3.4 Ingestion handler

```python
def _handle_drive_picker_selection(file_id: str) -> None:
    """Download, validate, and ingest a Drive file selected via the Picker.

    The file_id is the only value trusted from the Picker payload.
    Name and MIME type are fetched server-side via download_drive_file()
    and are authoritative for the spinner, provenance, and context.
    """
    with st.spinner("📥 Downloading from Drive..."):
        try:
            from utils.ga4_client import credentials_from_dict
            from utils.drive_client import download_drive_file

            creds = credentials_from_dict(st.session_state.ga4_creds)
            file_bytes, downloaded_name = download_drive_file(creds, file_id)
        except ValueError as e:
            st.error(f"❌ {e}")
            return
        except RuntimeError as e:
            st.error(f"❌ {e}")
            logger.warning(
                "Drive import failed",
                extra={"drive_error_category": "download_failed"},
            )
            return

    # Reuse file loader — wrap bytes in BytesIO
    from io import BytesIO

    class _DriveFile:
        def __init__(self, name: str, data: bytes):
            self.name = name
            self._data = data
        def read(self) -> bytes:
            return self._data

    drive_file = _DriveFile(downloaded_name, file_bytes)
    df, error, warning = load_file(drive_file)

    if error:
        st.error(f"❌ {error}")
        return

    if warning:
        st.warning(f"⚠️ {warning}")

    missing = validate_columns(df)
    if missing:
        st.warning(
            f"⚠️ Missing expected columns: {', '.join(missing)}. "
            "Some features may be limited."
        )

    # Use downloaded_name everywhere — server metadata is authoritative
    _populate_data_state(
        df, "drive", missing,
        file_bytes=file_bytes,
        display_name=downloaded_name,
    )
```

## v0.1.0 Safety Baseline Preservation

| v0.1.0 Principle | How v0.3.0 Preserves It |
|---|---|
| Least-privilege scopes | Reuses existing `drive.file` — no scope expansion. AST guard extended to reject `drive`, `drive.readonly`, `drive.metadata.readonly` |
| Session-only tokens | OAuth flow unchanged — tokens never persisted. Token passed to picker via JSON-serialized `<script>` tag, never string-replaced, never logged |
| AST scope guards | `test_static_analysis.py` extended to reject 3 forbidden Drive scopes |
| Zero file persistence | Downloaded bytes wrapped in `BytesIO`, processed in memory, never written to disk. Streamed downloads capped at 100 MB |
| Content-derived identity | `source_id` uses SHA-256 of file bytes — same dedup guarantee as uploads |
| Clear Data semantics | `clear_data()` removes Drive-imported DataContext identically to uploads |
| Session-scoped processing | Imported data cleared on session end; no Drive file IDs persisted |
| Error redaction | Drive errors are classified into user-facing messages; structured logs use an allowlisted error category/status only — never raw API error text, request URLs, file IDs, tokens, or exception representations |
| Token safety | No unescaped token in HTML; no token in logs, errors, or visible UI |

## Deferred to Future Versions

| Item | Rationale |
|---|---|
| Scheduled/bulk imports | Single-file picker only for v0.3.0 |
| Folder browsing | Requires `drive.readonly` scope — violates least-privilege |
| Drive file change detection | No polling/webhook; user re-selects file for latest version |
| Google Sheets multi-tab support | First sheet only; multi-tab adds UI complexity for sheet selection |
| Shared Drive support | Personal Drive only |
| Declared bidirectional component (if Option A succeeds) | Escalate only if needed; Option A is acceptable for v0.3.0 if Phase 0 gate passes |
| Inline OAuth in picker iframe | Third-party cookie restrictions block this; token injection is the reliable pattern |
| Drive file preview before import | Add only if users request it |

## Risk Register

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| **Phase 0 bridge fails (Option A)** | Medium | High — blocks Phase 3 | Option B (declared component) pre-designed and ready |
| **OAuth token expires between picker open and download** | Low | Medium | Token refresh in `download_drive_file()`; clear error suggesting reconnect |
| **Large Google Sheets export causes OOM** | Low | Medium | Streamed byte cap (Layer 2) prevents unbounded memory; 100 MB hard limit |
| **Picker API script blocked by CSP** | Low | Low | `st.components.v1.html()` iframes have permissive defaults |
| **Developer key missing from secrets** | Medium | Low | Actionable warning with setup instructions; no crash |
| **Google Sheets export returns empty data** | Low | Low | Zero-byte rejection in `download_drive_file()` catches this before context creation |
| **Picker loads gapi slowly (network)** | Low | Low | Button→spinner→picker flow; user sees loading state |
