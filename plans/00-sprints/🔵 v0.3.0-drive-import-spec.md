## Design Decisions

| # | Decision | Rationale |
|---|---|---|
| **D1** | Google Picker API over `drive.files.list` | Avoids scope expansion; picker uses existing `drive.file` scope; user explicitly selects each file |
| **D2** | Picker uses a declared bidirectional Streamlit custom component, selected by Phase 0 | `Streamlit.setComponentValue()` provides the supported value-return channel. Option A (hidden-input DOM bridge via `components.html()`) was rejected after the `srcdoc` iframe origin proved incompatible with Google Picker (403) |
| **D3** | Component configuration passed as runtime arguments (not HTML-embedded JSON). `Streamlit.setComponentValue()` returns only `{kind, requestId, fileId}` — no Picker metadata, no tokens, no raw errors | The declared component receives `oauthToken`, `developerKey`, `appId`, `appOrigin`, and `requestId` as structured args. It returns a minimal validated payload; server-side `files.get()` remains the authority for name, MIME type, and size |
| **D4** | Picker rendered on-demand (button-first UX), not passively because credentials exist | Reduces token-bearing iframe exposure; user explicitly initiates import |
| **D5** | `files.export` for Google Sheets, `files.get_media` for CSVs/XLSX | Google Sheets have no binary download via `files.get` — must export to CSV/XLSX |
| **D6** | Server-side metadata authority — ignore picker `name`/`mimeType`, fetch via `files.get(…fields=…)` | Client payload is untrusted; server metadata is authoritative for MIME allowlisting, filename, and size |
| **D7** | 3-layer file-size validation: metadata preflight + streamed byte cap + final `len()` check | Metadata `size` is unreliable for native Google Sheets; streamed byte cap prevents OOM; final check is a safety net |
| **D8** | Reuse existing `data_loader.load_file()` pipeline | Avoids duplicating validation, size checks, row limits, and truncation logic |
| **D9** | New `create_context_from_drive()` factory | Provenance distinguishes drive-import from upload: `"drive-import:{filename}"` vs `"upload:{filename}"` |
| **D10** | Google Picker requires a developer key (API key) in addition to the OAuth token; key stored in `st.secrets["GOOGLE_PICKER_API_KEY"]` | Picker documentation specifies `.setDeveloperKey()`; restricted to Picker API + app origin referrer |
| **D11** | Zero-byte files rejected in `download_drive_file()`, not deferred to context factory | User-facing error at download time is clearer; context factory requires non-empty bytes |

## Phase 0: Picker Transport Proof of Concept ✅ COMPLETE

**Completed:** 2026-07-31 | **Decision:** Option B — declared bidirectional Streamlit custom component | **Outcome:** Accepted

### Decision record

Option A (`st.components.v1.html()` plus hidden-input DOM bridge) was **rejected**.
The Picker ran inside an `about:srcdoc` iframe with opaque origin `null`; the
Picker request emitted an invalid iframe-derived parent identity and returned
403 despite a correct local top-level origin and HTTP referrer.

Option B uses a declared Streamlit component with the supported
`Streamlit.setComponentValue()` return channel. It passed the Phase 0
transport gates (Chrome/macOS) and is the **only permitted Picker transport**
for v0.3.0.

Full evidence: [`plans/00-sprints/✅ phase-0-debug-summary.md`](./✅%20phase-0-debug-summary.md)

### Production boundary

- Python passes the current OAuth access token, restricted Picker developer
  key, GCP project number, configured app origin, and server-generated request ID.
- The component opens Picker only after explicit user action.
- On selection, it returns the minimum payload: `{kind: "picked", requestId: "...", fileId: "..."}`.
- The wrapper validates the return schema (returns `PickerSelection | None`);
  the sidebar accepts a result only when its `requestId` matches the active
  server-side request.
- Picker-supplied name, MIME type, URL, and other callback metadata are
  discarded. Server-side `files.get()` remains authoritative.
- Cancel returns no selection value. Fixed, non-sensitive component status
  codes may be returned for expected errors.
- The component never logs, displays, persists, or sends tokens, API keys,
  raw callback objects, file names, MIME types, URLs, or raw errors to Python.

acceptance (Chrome/Windows, Safari/macOS, Firefox/macOS+Windows) is pending.

### 1.2 Drive download function (`utils/drive_client.py`)

```python
import io
from googleapiclient.http import MediaIoBaseDownload

# Supported MIME types for Drive import
DRIVE_IMPORT_MIME_TYPES = {
    "text/csv": ".csv",
    "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet": ".xlsx",
    "application/vnd.google-apps.spreadsheet": ".csv",
}

MAX_DRIVE_IMPORT_BYTES = 100 * 1024 * 1024  # 100 MB

GOOGLE_SHEETS_EXPORT_MIME = "text/csv"


def download_drive_file(
    credentials: Credentials,
    file_id: str,
) -> tuple[bytes, str]:
    """Download a file from Google Drive for import.

    Server-side metadata is authoritative — the file_id is an opaque
    token from the Picker; name, MIME type, and size are fetched from
    the Drive API, not from client-provided values.

    Size validation uses 3 layers:
    1. Metadata preflight — reject if 'size' field > 100 MB (fast).
    2. Streamed byte cap — hard-abort the download/export stream if
       accumulated bytes exceed 100 MB (catches Sheets with no preflight).
    3. Final check — verify len(bytes) ≤ 100 MB before returning.

    Zero-byte files are rejected with a clear user-facing error.

    Args:
        credentials: Valid OAuth credentials (with drive.file scope).
        file_id: Google Drive file ID from the Picker.

    Returns:
        Tuple of (file_bytes, normalized_filename).
        - Google Sheets: filename gets '.csv' extension if not already present.
        - CSV/XLSX: filename used as-is from server metadata.

    Raises:
        DriveImportError: On any Drive-import failure — API errors (404/403),
            oversize, empty file, or unsupported MIME. Carries a fixed code
            (`not_found`, `access_denied`, `unsupported_type`, `too_large`,
            `empty_file`, `download_failed`) and a fixed user-safe message.
    """
    ...
```

**Implementation details:**

1. **Fetch server metadata** — `files.get(fileId=file_id, fields='name,mimeType,size')`. Use the returned values for validation. Do NOT trust the Picker payload's `name` or `mimeType`.

2. **MIME allowlist** — only `DRIVE_IMPORT_MIME_TYPES` keys are permitted. Reject anything else with `DriveImportError("unsupported_type", "This file type isn't supported. Please select a CSV, XLSX, or Google Sheets file.")`.

3. **3-layer size validation:**
   - **Layer 1 (metadata preflight):** If the metadata `size` field is present and > `MAX_DRIVE_IMPORT_BYTES`, raise `DriveImportError("too_large", …)` immediately. This handles CSVs and XLSXs. Note: Google Sheets metadata may omit or misrepresent the byte size — this is only a fast path.
   - **Layer 2 (streamed byte cap):** For `files.export_media()` (Google Sheets), use chunked download via `MediaIoBaseDownload` into a bounded writer whose `write()` rejects any write that would exceed the cap:
     ```python
     import io

     class _BoundedBytesIO(io.BytesIO):
         """BytesIO that rejects writes exceeding MAX_DRIVE_IMPORT_BYTES.

         Rejects the chunk before it is retained in the in-memory output
         buffer, preventing unbounded accumulation from a large Google
         Sheets export that lacks a metadata size.
         """
         def write(self, data: bytes) -> int:
             if self.tell() + len(data) > MAX_DRIVE_IMPORT_BYTES:
                 raise DriveImportError(
                     "too_large",
                     "The selected file exceeds the 100 MB limit.",
                 )
             return super().write(data)
     ```
     This preserves the hard-cap intent for native Google Sheets exports instead of merely detecting oversize after buffer growth.
   - **Layer 3 (final check):** After download, verify `len(file_bytes) <= MAX_DRIVE_IMPORT_BYTES`; raise `DriveImportError("too_large", …)` if exceeded. Safety net.

4. **Zero-byte rejection:** If `file_bytes` is empty after download, raise `DriveImportError("empty_file", "The selected file is empty.")`. Do not defer this to `create_context_from_drive()`.

5. **Google Sheets filename:** `files.export` exports the first sheet only. Build the filename as:
   ```python
   if name.lower().endswith('.csv'):
       final_name = name
   else:
       final_name = f"{name}.csv"
   ```
   This avoids `report.csv.csv` when the Sheet is already named `report.csv`.

6. **Google Sheets product behavior:** The returned CSV contains only the **first sheet** of the workbook. This must be stated in user-facing copy (sidebar, error messages, Learn page). Do not claim or imply multi-sheet import.

7. **Error handling:** Wrap all Drive API calls in try/except `HttpError` and raise a small public typed exception carrying a fixed machine-readable code. *(Refinement: Phase 1 (commit `9754189`) shipped allowlisted `RuntimeError` messages with message-based categories; the typed `DriveImportError` lands with Phase 2/3 and is the target contract for Phase 3 UX mapping.)*
   ```python
   class DriveImportError(RuntimeError):
       """Drive import failure with a fixed, non-sensitive code."""
       def __init__(self, code: str, message: str) -> None:
           super().__init__(message)
           self.code = code
   ```
   Fixed codes: `not_found`, `access_denied`, `unsupported_type`, `too_large`, `empty_file`, `download_failed`. The displayed message stays fixed and user-safe; never attach raw Google errors, request URLs, or file IDs to the exception or its message. Mapping:
   - 404 → `DriveImportError("not_found", "File not found or access denied. Check that you have permission.")`
   - 403 → `DriveImportError("access_denied", "Access denied. Try reconnecting your Google account.")`
   - Unsupported MIME → `DriveImportError("unsupported_type", …)`
   - Oversize → `DriveImportError("too_large", …)`
   - Empty → `DriveImportError("empty_file", "The selected file is empty.")`
   - Other → `DriveImportError("download_failed", "Could not download the file. Please try again.")`
   - Never expose raw API errors, file IDs, or token fragments in exception messages.
   - **Structured logging only:** Log an allowlisted error category/status code — prefer `error.code` from the typed exception — never the raw `HttpError` text, request URL, file ID, or full exception representation. Do NOT use `exc_info=True` in Drive error handlers — exception tracebacks can reproduce the raw error payload including request URLs.

8. **Token refresh:** Use the existing `_build_drive_service()` pattern — `credentials.refresh(Request())` if expired.

9. **No disk writes:** All bytes stay in memory (`BytesIO`). Never call `.write()` to a filesystem path.

### 2.1 Drive Context factory (`utils/data_context.py`)

```python
def create_context_from_drive(
    df: pd.DataFrame,
    file_bytes: bytes,
    display_name: str = "",
) -> DataContext:
    """Create a DataContext from a Google Drive import.

    Identical to create_context_from_upload in mechanics, but sets
    provenance to "drive-import:{name}" (vs "upload:{name}") and
    source_id prefix to "drive:" (vs "file:").

    Callers MUST ensure file_bytes is non-empty — download_drive_file()
    rejects zero-byte files before this factory is reached.

    Raises:
        TypeError: if df is not a pandas DataFrame.
        ValueError: if file_bytes is empty or not bytes.
    """
    if not isinstance(df, pd.DataFrame):
        raise TypeError("df must be a pandas DataFrame")
    if not isinstance(file_bytes, bytes) or not file_bytes:
        raise ValueError("file_bytes must be non-empty bytes")

    content_hash = hashlib.sha256(file_bytes).hexdigest()[:24]
    base = df.copy(deep=True)
    return DataContext(
        source_id=f"drive:{content_hash}",
        version=0,
        raw_df=df.copy(deep=True),
        base_df=base,
        active_df=base.copy(deep=True),
        provenance=(f"drive-import:{display_name}",) if display_name else ("drive-import:unknown",),
    )
```

**Source identity rule:** `source_id = "drive:" + SHA-256(content)[:24]`. Identical bytes imported twice share a Drive source identity, while the same bytes uploaded locally stay distinguishable via the `file:` prefix. Never include the file ID or file name in `source_id` — it is content-derived only.

### 2.2 Sidebar pipeline (`components/sidebar.py`)

**Transaction boundary:** one helper prepares the candidate context **without
mutating `st.session_state`**. The unified `_build_context_for_source()`
dispatches by source — for `source="drive"` it delegates to the
Drive-specific wrapper `_build_drive_context()`, which wraps
`create_context_from_drive()`:

```python
def _build_drive_context(
    df: pd.DataFrame,
    file_bytes: bytes,
    display_name: str,
) -> DataContext:
    return create_context_from_drive(df, file_bytes, display_name)

# _build_context_for_source(prepared_df, source=..., file_bytes=..., ...)
# routes source="drive" -> _build_drive_context(...) and keeps the
# upload/GA4 branches on their existing factories.
```

Then `_populate_data_state()` follows the atomic contract (shared with Phase 3):

1. Build the candidate `DataContext` in a local variable.
2. Complete any dependent state preparation.
3. Assign `st.session_state.data_context` **only after all steps succeed**.
4. Clear/reset derived state only after that successful assignment.

Do **not** implement the Drive branch as only:

```python
candidate = _build_drive_context(df, file_bytes, display_name)
st.session_state.data_context = candidate
```

The current `_populate_data_state()` is not atomic: its earlier statements already
mutate `custom_metrics`, `missing_columns`, `stats`, `quality_report`, `summary`,
`chat_history`, `data_source`, and `data_cleared` before `data_context` is
created. Phase 2 must prepare **all** values locally, construct the candidate
context, then commit session-state changes as one final block:

```python
def _populate_data_state(...) -> None:
    prepared_df = _prepare_dates(df.copy(deep=True))
    candidate_context = _build_context_for_source(
        prepared_df,
        source=source,
        file_bytes=file_bytes,
        display_name=display_name,
        ga4_metadata=ga4_metadata,
    )
    candidate_stats = get_dataset_stats(prepared_df)
    candidate_missing = list(missing)
    candidate_quality = assess_data_quality(prepared_df, candidate_missing)

    # Commit only after every preceding operation succeeds.
    st.session_state.data_context = candidate_context
    st.session_state.custom_metrics = {}
    st.session_state.missing_columns = candidate_missing
    st.session_state.stats = {
        **candidate_stats,
        "missing_columns": candidate_missing,
    }
    st.session_state.quality_report = candidate_quality
    st.session_state.summary = None
    st.session_state.chat_history = []
    st.session_state.data_source = source
    st.session_state.data_cleared = False
```

This prepare-then-commit model should apply to the upload and GA4 paths as well,
where practical — it is safer than making Drive uniquely atomic.

### 3.2 Button-first UX (`components/sidebar.py`)

Do NOT render the token-bearing component passively because credentials exist.

def _cancel_drive_import() -> None:
    """Reset the drive-import flow to idle; safe from any config branch."""
    st.session_state._drive_import_requested = False
    st.session_state.pop("_drive_request_id", None)

def _validate_picker_origin(origin: str, *, is_development: bool) -> str:
    """Validate Picker origin configuration; fail closed on any deviation.

    Rejects a path, query, fragment, credentials, or non-default path form;
    enforces HTTPS and non-local hosts outside development.
    """
    from urllib.parse import urlparse

    parsed = urlparse(origin)
    valid = (
        parsed.scheme in {"http", "https"}
        and bool(parsed.netloc)
        and parsed.path in {"", "/"}
        and not parsed.params
        and not parsed.query
        and not parsed.fragment
        and not parsed.username
        and not parsed.password
    )
    if not valid:
        raise ValueError("invalid Picker origin configuration")

    if not is_development and parsed.scheme != "https":
        raise ValueError("production Picker origin must use HTTPS")

    if not is_development and parsed.hostname in {"localhost", "127.0.0.1"}:
        raise ValueError("production Picker origin must not be local")

    return origin.rstrip("/")

### 3.4 Ingestion handler

```python
def _handle_drive_picker_selection(file_id: str) -> None:
    """Download, validate, and ingest a Drive file selected via the Picker.

    The file ID is the only Picker-supplied value accepted as an opaque, current-request capability. It is not trusted as metadata or authorization; the server immediately validates access and retrieves authoritative metadata through the Drive API.
    Name and MIME type are fetched server-side via download_drive_file()
    and are authoritative for the spinner, provenance, and context.
    """
    with st.spinner("📥 Downloading from Drive..."):
        try:
            from utils.ga4_client import credentials_from_dict
            from utils.drive_client import DriveImportError, download_drive_file

            creds = credentials_from_dict(st.session_state.ga4_creds)
            file_bytes, downloaded_name = download_drive_file(creds, file_id)
        except ValueError as e:
            st.error(f"❌ {e}")
            return
        except DriveImportError as e:
            st.error(f"❌ {e}")
            logger.warning(
                "Drive import failed",
                extra={"drive_error_category": e.code},
            )
            return

    # Reuse file loader — wrap bytes in BytesIO
    from io import BytesIO

    class _DriveFile:
        def __init__(self, name: str, data: bytes):
            self.name = name
            self._data = data
        def read(self) -> bytes:
            return self._data

    drive_file = _DriveFile(downloaded_name, file_bytes)
    df, error, warning = load_file(drive_file)

    if error:
        st.error(f"❌ {error}")
        return

    if warning:
        st.warning(f"⚠️ {warning}")

    missing = validate_columns(df)
    if missing:
        st.warning(
            f"⚠️ Missing expected columns: {', '.join(missing)}. "
            "Some features may be limited."
        )

    # Use downloaded_name everywhere — server metadata is authoritative
    _populate_data_state(
        df, "drive", missing,
        file_bytes=file_bytes,
        display_name=downloaded_name,
    )
```

**Atomic import rule:** `_populate_data_state()` must construct the new Drive
DataContext in a local variable and assign `st.session_state.data_context`
only after all parsing, validation, and context construction have succeeded.
It must not call `clear_data()` at import start. If download, parsing,
validation, or context construction fails, the existing DataContext remains
unchanged and no partial Drive-import state survives.

## v0.1.0 Safety Baseline Preservation

| v0.1.0 Principle | How v0.3.0 Preserves It |
|---|---|
| Least-privilege scopes | Reuses existing `drive.file` — no scope expansion. AST guard extended to reject `drive`, `drive.readonly`, `drive.metadata.readonly` |
| Session-only tokens | OAuth flow unchanged — tokens never persisted. Token passed only as a declared-component runtime argument after explicit user action; never in HTML, logs, errors, or visible UI |
| AST scope guards | `test_static_analysis.py` extended to reject 3 forbidden Drive scopes |
| Zero file persistence | Downloaded bytes wrapped in `BytesIO`, processed in memory, never written to disk. Streamed downloads capped at 100 MB |
| Content-derived identity | `source_id` uses SHA-256 of file bytes — same dedup guarantee as uploads |
| Clear Data semantics | `clear_data()` removes Drive-imported DataContext identically to uploads |
| Session-scoped processing | Imported data cleared on session end; no Drive file IDs persisted |
| Error redaction | Drive errors are classified into user-facing messages; structured logs use an allowlisted error category/status only — never raw API error text, request URLs, file IDs, tokens, or exception representations |
| Token safety | Token passed only as a declared-component runtime argument after explicit user action; never in HTML, logs, errors, or visible UI |
