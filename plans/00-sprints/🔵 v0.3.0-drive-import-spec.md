## Design Decisions (carried forward from design doc)

| # | Decision | Rationale |
|---|---|---|
| **D1** | Google Picker API over `drive.files.list` | Avoids scope expansion; picker uses existing `drive.file` scope; user explicitly selects each file |
| **D2** | `st.components.v1.html()` iframe for picker | No frontend build pipeline needed; same pattern as onboarding tour; picker is self-contained widget |
| **D3** | Hidden `st.text_input` bridge for postMessage → Python | `components.html()` doesn't support bidirectional component values; text input bridge is the standard Streamlit workaround for JS→Python communication |
| **D4** | OAuth token passed to iframe, not authenticated inside it | Third-party cookie restrictions break OAuth in iframes; token obtained at Streamlit page level and injected into HTML |
| **D5** | `files.export` for Google Sheets, `files.get_media` for CSVs/XLSX | Google Sheets have no binary download via `files.get` — must export to CSV/XLSX |
| **D6** | Reuse existing `data_loader.load_file()` pipeline | Avoids duplicating validation, size checks, row limits, and truncation logic |
| **D7** | New `create_context_from_drive()` factory | Provenance distinguishes drive-import from upload: `"drive-import:{filename}"` vs `"upload:{filename}"` |

### Picker-to-Python communication bridge

The critical design challenge: `st.components.v1.html()` cannot synchronously return values from the iframe to Python (as learned with the onboarding tour in v0.2.0). The solution uses a hidden `st.text_input` as a bridge:

```text
User clicks picker file
  ↓
Picker callback extracts fileId + mimeType
  ↓
JavaScript sets hidden text input value + dispatches 'input' event
  ↓
Streamlit detects input change → rerun
  ↓
Python reads fileId from session_state → downloads file
  ↓
Python clears the bridge value (prevents re-trigger)
```

This pattern is used in production Streamlit apps (`st_javascript` package, `streamlit-js-eval`) and avoids building a declared custom component for what is fundamentally a one-shot user action.

**Implementation details:**

1. **Fetch metadata first** — `files.get(fileId=file_id, fields='name,mimeType,size')` to get filename, MIME type, and size before downloading bytes. This avoids downloading a 500 MB file only to reject it.

2. **Size validation** — if `size` > `100 * 1024 * 1024`, raise `ValueError` with a user-friendly message. Match existing `MAX_FILE_SIZE_MB` in `data_loader.py`.

3. **MIME branching:**
   - `application/vnd.google-apps.spreadsheet` → `files.export_media(mimeType='text/csv')` — returns raw CSV bytes. Build filename as `{original_name}.csv`.
   - `text/csv` or `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` → `files.get_media()` — returns raw bytes directly.
   - Any other MIME type → raise `ValueError(f"Unsupported file type: {mime_type}")`.

4. **Error handling:** Wrap API calls in try/except `HttpError`. Distinguish 404 (file not found / permissions), 403 (token issue), and other errors for clear user messaging.

5. **Token refresh:** Use existing `_build_drive_service()` pattern — credentials are refreshed if expired before the API call.

### 2.1 Drive Context factory (`utils/data_context.py`)

```python
def create_context_from_drive(
    df: pd.DataFrame,
    file_bytes: bytes,
    display_name: str = "",
) -> DataContext:
    """Create a DataContext from a Google Drive import.

    Identical to create_context_from_upload in mechanics, but sets
    provenance to distinguish Drive imports from file uploads. The
    source_id is still content-derived (SHA-256 of bytes) — same
    dedup guarantees as upload.

    Args:
        df: Validated DataFrame from data_loader.
        file_bytes: Raw file bytes (for content-derived source_id).
        display_name: Human-readable filename from Drive metadata.

    Returns:
        DataContext with provenance=("drive-import:{display_name}",).

    Raises:
        TypeError: if df is not a pandas DataFrame.
        ValueError: if file_bytes is empty or not bytes.
    """
    if not isinstance(df, pd.DataFrame):
        raise TypeError("df must be a pandas DataFrame")
    if not isinstance(file_bytes, bytes) or not file_bytes:
        raise ValueError("file_bytes must be non-empty bytes")

    content_hash = hashlib.sha256(file_bytes).hexdigest()[:24]
    base = df.copy(deep=True)
    return DataContext(
        source_id=f"drive:{content_hash}",
        version=0,
        raw_df=df.copy(deep=True),
        base_df=base,
        active_df=base.copy(deep=True),
        provenance=(f"drive-import:{display_name}",) if display_name else ("drive-import:unknown",),
    )
```

Key difference from `create_context_from_upload`: `source_id` prefix is `"drive:"` (not `"file:"`) and provenance is `"drive-import:{name}"` (not `"upload:{name}"`). This allows the summary/chat/export to distinguish data sources without coupling to the import mechanism.

```python
  const OAUTH_TOKEN = "__OAUTH_TOKEN__";
  const DEVELOPER_KEY = "";  // Not needed when using OAuth

  function openPicker() {
    document.getElementById('error').textContent = '';
    document.getElementById('status').textContent = 'Opening file picker...';

    gapi.load('picker', () => {
      const view = new google.picker.DocsView(google.picker.ViewId.DOCS)
        .setMimeTypes(
          'application/vnd.google-apps.spreadsheet,' +
          'text/csv,' +
          'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet'
        )
        .setMode(google.picker.DocsViewMode.LIST);

      const picker = new google.picker.PickerBuilder()
        .addView(view)
        .setOAuthToken(OAUTH_TOKEN)
        .setAppId(APP_ID)
        .setCallback(pickerCallback)
        .build();

      picker.setVisible(true);
    });
  }

  function pickerCallback(data) {
    if (data[google.picker.Response.ACTION] === google.picker.Action.PICKED) {
      const doc = data[google.picker.Response.DOCUMENTS][0];
      const fileId = doc[google.picker.Document.ID];
      const fileName = doc[google.picker.Document.NAME];
      const mimeType = doc[google.picker.Document.MIME_TYPE];

      document.getElementById('status').textContent =
        'Selected: ' + fileName;

      // Bridge: set the hidden Streamlit text input in the parent window
      try {
        const payload = JSON.stringify({
          fileId: fileId,
          name: fileName,
          mimeType: mimeType
        });
        // Find the hidden input in the parent document and set its value
        const parentDoc = window.parent.document;
        const bridgeInput = parentDoc.querySelector(
          'input[aria-label="_drive_picker_bridge"]'
        );
        if (bridgeInput) {
          const nativeInputValueSetter =
            Object.getOwnPropertyDescriptor(
              window.HTMLInputElement.prototype, 'value'
            ).set;
          nativeInputValueSetter.call(bridgeInput, payload);
          bridgeInput.dispatchEvent(new Event('input', { bubbles: true }));
        }
      } catch (e) {
        document.getElementById('error').textContent =
          'Failed to send file selection. Please try again.';
      }
    } else if (data[google.picker.Response.ACTION] === google.picker.Action.CANCEL) {
      document.getElementById('status').textContent = 'No file selected.';
    }
  }
</script>
</body>
</html>"""
```

**Key design points:**
- OAUTH_TOKEN is injected at render time — obtained from `st.session_state.ga4_creds`
- No DEVELOPER_KEY needed when using OAuth (the token authorizes the picker)
- Picker filters to spreadsheets + CSVs only — no arbitrary file browsing
- Bridge sends `{fileId, name, mimeType}` as JSON via the hidden input pattern
- Error handling in the callback — if bridging fails, shows inline error

### 3.2 Sidebar render function (`components/sidebar.py`)

```python
def _render_drive_import() -> None:
    """Render the Google Drive import button + picker.

    Only shown when OAuth credentials are valid. The picker opens in an
    iframe via st.components.v1.html(). A hidden st.text_input receives
    the selected file ID via the postMessage→DOM bridge pattern.
    """
    if st.session_state.ga4_creds is None:
        return

    st.divider()
    theme = st.session_state.get("theme", "dark")
    section_color = "#1f2937" if theme == "light" else "#f0f0f5"
    st.markdown(
        f'<p style="font-size:0.8rem;font-weight:600;color:{section_color};'
        f'margin-bottom:0.3rem;">📂 Google Drive</p>',
        unsafe_allow_html=True,
    )

    # Hidden bridge input — receives picker selection via JavaScript
    bridge_value = st.text_input(
        "Picker bridge",
        key="_drive_picker_bridge",
        label_visibility="collapsed",
    )

    # Render the picker iframe (always visible when OAuth is active)
    try:
        from utils.ga4_client import credentials_from_dict
        creds = credentials_from_dict(st.session_state.ga4_creds)
        if creds.expired and creds.refresh_token:
            creds.refresh(Request())
        oauth_token = creds.token

        project_id = os.getenv("GOOGLE_CLOUD_PROJECT", "")
        html = _PICKER_HTML_TEMPLATE.replace("__OAUTH_TOKEN__", oauth_token)
        html = html.replace("__APP_ID__", project_id)

        components.html(html, height=120, scrolling=False)
    except Exception:
        st.caption("⚠️ Could not initialize Drive picker. Try reconnecting your Google account.")

    # Process picker selection
    if bridge_value:
        _handle_drive_picker_selection(bridge_value)
        # Clear the bridge to prevent re-triggering on rerun
        st.session_state._drive_picker_bridge = ""
        st.rerun()


def _handle_drive_picker_selection(payload: str) -> None:
    """Download, validate, and ingest a Drive file selected via the Picker."""
    try:
        data = json.loads(payload)
    except json.JSONDecodeError:
        st.error("Could not read the file selection. Please try again.")
        return

    file_id = data.get("fileId")
    filename = data.get("name", "unknown")
    mime_type = data.get("mimeType", "")

    if not file_id:
        return

    with st.spinner(f"📥 Downloading {filename} from Drive..."):
        try:
            from utils.ga4_client import credentials_from_dict
            from utils.drive_client import download_drive_file

            creds = credentials_from_dict(st.session_state.ga4_creds)
            file_bytes, downloaded_name, detected_mime = download_drive_file(
                creds, file_id
            )
        except ValueError as e:
            st.error(f"❌ {e}")
            return
        except RuntimeError as e:
            st.error(
                "❌ Could not download the file. "
                "Check that you have access and try again."
            )
            logger.warning("Drive download error", exc_info=True)
            return

    # Reuse existing file loader — wrap bytes in BytesIO
    from io import BytesIO

    # data_loader.load_file expects a file-like object with .name
    class _DriveFile:
        def __init__(self, name: str, data: bytes):
            self.name = name
            self._data = data
        def read(self) -> bytes:
            return self._data

    drive_file = _DriveFile(downloaded_name, file_bytes)

    df, error, warning = load_file(drive_file)

    if error:
        st.error(f"❌ {error}")
        return

    if warning:
        st.warning(f"⚠️ {warning}")

    missing = validate_columns(df)
    if missing:
        st.warning(
            f"⚠️ Missing expected columns: {', '.join(missing)}. "
            "Some features may be limited."
        )

    _populate_data_state(
        df,
        "drive",
        missing,
        file_bytes=file_bytes,
        display_name=filename,
    )
```

### 4.2 Error message audit

Ensure all user-facing Drive import errors are:
- **Actionable:** Tell the user what went wrong and what to do next
- **Not leaking:** No raw API errors, stack traces, file IDs, or token fragments
- **Consistent:** Follow the existing pattern: `"❌ {short message}. {suggested action}."`

| Scenario | User-facing message |
|---|---|
| File > 100 MB | `"❌ File is too large (X MB). Maximum is 100 MB. Export a narrower date range from GA4 and try again."` |
| Unsupported type | `"❌ This file type isn't supported. Please select a CSV, XLSX, or Google Sheets file."` |
| Download failed | `"❌ Could not download the file. Check that you have access and try again."` |
| Parse failed | `"❌ We couldn't read this file. Confirm that it is a valid CSV or XLSX export and try again."` (reuses existing) |
| Picker cancelled | No message — just the picker closes silently |
| Token expired | `"⚠️ Your Google sign-in has expired. Please reconnect in the sidebar."` |

## v0.1.0 Safety Baseline Preservation

Every v0.1.0 hardening principle is maintained:

| v0.1.0 Principle | How v0.3.0 Preserves It |
|---|---|
| Least-privilege scopes | Reuses existing `drive.file` — no scope expansion. AST guard extended to reject `drive`, `drive.readonly`, `drive.metadata.readonly` |
| Session-only tokens | OAuth flow unchanged — tokens never persisted. Token passed to picker iframe as a render-time string, not stored |
| AST scope guards | `test_static_analysis.py` extended to reject 3 forbidden Drive scopes |
| Zero file persistence | Downloaded bytes wrapped in `BytesIO`, processed in memory, never written to disk |
| Content-derived identity | `source_id` uses SHA-256 of file bytes (prefix `"drive:"`) — same dedup guarantee as uploads |
| Clear Data semantics | `clear_data()` removes Drive-imported DataContext identically to uploads |
| Session-scoped processing | Imported data cleared on session end; no Drive file IDs persisted |
| Error redaction | Drive API errors classified into user-facing messages; raw errors logged, not shown |

## Deferred to Future Versions

| Item | Rationale |
|---|---|
| **Scheduled/bulk imports** | Single-file picker only for v0.3.0; batch adds complexity (multiple downloads, merged DataFrames) without clear user need |
| **Folder browsing** | Picker filters to individual files — folder access would require `drive.readonly` scope, violating least-privilege |
| **Drive file change detection** | No polling/webhook refresh; user re-selects file to get latest version |
| **Google Sheets multi-tab support** | `files.export` exports the first sheet only; multi-tab adds UI complexity for sheet selection |
| **Shared Drive support** | Personal Drive only; Shared Drives require additional scope and API parameters |
| **Declared bidirectional component** | Picker bridge pattern is simpler; escalate to custom component only if postMessage reliability becomes an issue |
| **Inline OAuth in picker iframe** | Third-party cookie restrictions break this; token injection is the reliable pattern |
| **Drive file preview before import** | Add only if users request it; adds complexity (metadata pane, sample row display) |

## Risk Register

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| **Picker bridge unreliable** | Medium | High — file selection silently lost | Hidden input pattern tested in 3 browsers; fallback error message in picker callback |
| **Google Sheets export returns empty data** | Low | Medium — user sees empty dataset | data_loader already handles empty DataFrame with clear error |
| **OAuth token expires between picker open and download** | Low | Medium — download fails | Token refresh in `download_drive_file`; clear error message suggesting reconnect |
| **Picker API script blocked by CSP/CORS** | Low | Low | `st.components.v1.html()` iframes have permissive defaults; Streamlit config already allows external scripts |
| **Large CSV causes OOM during download** | Low | Medium | 100 MB size check before download; 50k row limit after parse |
| **Picker loads gapi slowly (network)** | Low | Low | Picker iframe stays at 120px height; button state shows "Opening..." |
