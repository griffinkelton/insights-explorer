# Store Drift Matrix — captured `explorer-store.tsx` vs F3's wiring assumptions

**Source:** `whisperer-30-reference/UI-CAPTURE-8b4b7b9/src/lib/explorer-store.tsx` (243 lines, frozen @ `8b4b7b9`, captured 2026-08-06) vs `migration/freebuff-prompt-wire-react-store.md` (F3, the 13-step store-wiring prompt).
**Purpose:** the precise instruction set for Phase 4 store wiring. F3 was written against the prototype's *documented* contract; the capture reveals the *actual* API. Where they diverge, the canonical migration decision in this matrix wins.
**Status:** planning reference (not default agent context) — Phase 4 input, per the doc-role split.

| Captured store behavior | F3 assumption | Canonical migration decision | Required change |
|---|---|---|---|
| `loadData(name?: string)` — fakes a load with `setTimeout(1100ms)` + `defaultSource` | `loadData(file?: File, source?: "upload"\|"ga4"\|"drive")` → real `POST /api/v1/upload` | F3's signature supersedes; the mock's `name` param has no API equivalent | Replace the body with a real upload; set `source` from the API `{ dataset }` response; never fall back to `defaultSource` |
| `failLoad()` — sets `error` to the hardcoded string "Unsupported file type. Upload a .csv or .xlsx export." | not mentioned | Keep the member; the message must come from the server's typed error taxonomy, not a hardcoded string | Map server error codes → message (matches upload/Dry errors) |
| `clearData()` — resets `source`/`loadState`/`error`/`summary`/`summaryState`/`chat` (**not** `filters`/`metrics`) | implies `clearData` | Extend: also reset filters+metrics (to server defaults / empty) and call the server session clear so derived state dies with the dataset — retention policy: Clear Data deletes dataset, previews, analysis cache, chat context, and temp exports immediately | Add filters/metrics reset + server `clear` call (Phase 1 endpoint, Phase 3 session wiring) |
| **Hardcoded seeds:** `initialFilters` (date "Jan – Mar 2024", page "/home") and `initialMetrics` (sessions, users, engagement_rate, bounce_rate) | none | Production must not seed mock defaults — start empty; real filters/metrics hydrate from `GET /api/v1/data/context` after a dataset loads | Remove seeds; hydrate from server dataset context |
| `addFilter`/`removeFilter` + `addMetric`/`removeMetric` — local-only state, ids `f${Date.now()}` / `me${Date.now()}` | **omitted from F3's step-9 interface entirely** | Keep the members — F3 §9 must **union**, not replace the interface. Filter/metric state is server-owned (server-session model) → sync via API in Phase 3, not silent local-only state | F3 §9 union + define server-sync semantics |
| `generateSummary()` — sets `summaryState: "streaming"`, calls `streamAi({ mode: "summary" })` with **no dataset context in the payload** | adds `generateSummary` → `streamAi({ mode: "summary" })` | Payload must carry the server session/dataset reference plus current filters/metrics (server-owned session model) | Add dataset/context fields to the summary request |
| `sendMessage(text)` — client-side command router (`/help`, `/summary`, `/equity`, `/funnel`, `/clear`) using **hardcoded prompts**; history = last 8 messages, last message re-appended as the (possibly command-expanded) prompt; optimistic append tracked by `streamingId` | not detailed | Command routing belongs server-side (`utils/commands.py`); never hardcode BrainGuide/equity prompts in the store — prompt source is `utils/prompt_templates.py` | Move command resolution to FastAPI; store keeps optimistic append + reconnect-safe retry |
| `clearChat()` — `setChat([])` | **omitted from F3 §9** | Keep; server chat context must clear in the same call | F3 §9 union + server clear |
| `ChatMessage.timestamp` — `toLocaleTimeString([], { hour, minute })` at message creation | F3's sketch omits the field | Keep client-side display timestamps; prefer server timestamps when present | `api-types.ts` `ChatMessage` includes `timestamp` |
| `streamAi()` — relative `/api/chat` (TanStack Start route), plain-text `getReader()`/`TextDecoder` accumulation, **no `credentials`** | update to `/api/v1/chat` | Direct `POST /api/v1/chat` with `credentials: "include"`; **no proxy** (same-origin deployment — F3's proxy option removed 2026-08-06); plain-text reader is valid only for the locked plain-SSE wire format (open decision #1) | URL + credentials; delete `src/routes/api/chat.ts` |
| `streamingId` — tracks the in-flight assistant reply id | omitted | Keep — required for the Phase 4 chat-reconnect rule (retain the user message, render partial output safely, retry without duplicate assistant messages) | Retain; reconnect logic keyed on it |
| `useTheme()` — localStorage `"ie-theme"`, default `"dark"`, `classList.toggle("dark")` | not mentioned (separate concern) | Keep; verify against the repo's Streamlit theme-toggle behavior. localStorage is fine — theme is non-sensitive, not session state | Parity check only |
| `ExplorerValue` interface — 20 members (state + `loadData`/`failLoad`/`clearData`/`addFilter`/`removeFilter`/`addMetric`/`removeMetric`/`generateSummary`/`sendMessage`/`clearChat`) | F3 §9 **replaces** it with a shorter list that omits the filter/metric/`sendMessage`/`clearChat` members | **Union:** keep every existing member, then add the new API members (`connectGA4`, `handleGA4Callback`, `connectDrive`, `downloadFromDrive`, `fetchQuality`/`Charts`/`Forecast`/`Funnel`, `exportData`) **plus** `setSourceFromApi` (F4 §11) | F3 §9 rewritten as a union, never a wholesale replacement |
| Types imported from `./mock-ga4` (`defaultSource`, `ChatMessage`, `DataSource`) | `api-types.ts` (step 12) | Types move to `api-types.ts` (canonical, generated/validated from OpenAPI); `api.ts` normalizes snake_case → camelCase once; the store never imports from mock fixtures | Remove the mock import; import types from `api-types` |
